# healing

The off-device half of self-healing Hex: test sets, evaluation, statistics and, later, capture,
labels, vocabulary mining and fine-tuning. The plan is in
[`docs/plans/self-healing/`](../docs/plans/self-healing/README.md).

It never changes Hex's behaviour on its own. It reads Hex's output, runs Hex's own
`hex benchmark-transcription`, and writes under `$HEALING_HOME`
(default `~/Library/Application Support/hex-healing`). Audio and datasets live there, never in
this repo.

## Install

```sh
cd healing
uv sync
uv run pytest
```

Python 3.12 and [uv](https://docs.astral.sh/uv/). The benchmark needs a `hex` binary: `$HEX_BIN`,
else this checkout's `target/release/hex`, else the installed `/Applications/Hex.app`.

## Running your own Hex build

Self-healing needs Hex changes that aren't released, so the Hex you dictate with is a local build of
this branch, installed as the only `/Applications/Hex.app`. Without a Developer ID certificate, build
it ad-hoc signed with updates off:

```sh
cd ..                      # repo root
HEX_RELEASE_UNSIGNED=1 HEX_LOCAL_BUILD=1 scripts/install-app.sh
rm -rf target/app/Hex.app  # so macOS never launches the build copy instead
```

Put the CLI on your PATH once: `ln -s /Applications/Hex.app/Contents/MacOS/hex ~/.local/bin/hex`.

- `HEX_RELEASE_UNSIGNED=1` keeps the normal app name and bundle id (`anomaly.hex`), so it uses the
  usual `~/Library/Application Support/hex` data folder: models, settings and History carry over.
- `HEX_LOCAL_BUILD=1` turns updates off, so it never replaces itself with an official release.
- `install-app.sh` stops the running Hex, replaces `/Applications/Hex.app` and opens it.
- Don't use `HEX_TEST_BUILD=1` for this: it builds `Hex Test.app` with its own `hex-test` data folder,
  which `healing` doesn't read unless `HEX_BIN` points at it.
- A plain `scripts/install-app.sh` needs `HEX_TEAM_ID` and a Developer ID identity, and fails without them.

The signature is ad-hoc, so macOS ties the Accessibility grant to that exact binary and every rebuild
invalidates it, even though System Settings still shows Hex as allowed. If Hex says "Waiting for setup"
or the shortcut stops working after a rebuild, reset the grant and relaunch, then allow Hex again if
asked:

```sh
tccutil reset Accessibility anomaly.hex && hex quit; open /Applications/Hex.app
```
 Turn on Settings › Labs › Keep
recordings, or `healing collect` has no audio to copy.

## Commands

| Command | What it does |
|---|---|
| `healing collect` | Copies Hex's History (`hex history --json --raw`) and kept recordings into `dataset.sqlite` and `audio/<sha256>.flac`. Idempotent. Entries Hex later deletes stay. Labels follow the run once at its end, for every clip it inserted or changed (never per row); everything else is labelled by `label all` and `split build`. |
| `healing status [--json]` | Clip count, bytes against the budget, clusters, the model registry's object bytes (`registry_object_bytes`), and warnings such as History expiring uncollected entries, or `watch_needs_reviews` while `healing watch` waits for reviewed clips from after a promotion (its waiting line is shown as `watch`). `--list` lists every warning code. |
| `healing prune [--budget B] [--k K] [--dry-run]` | Clusters near-duplicate text, keeps k audio files per cluster, and evicts the most redundant, oldest weak audio to hold the budget. |
| `healing clean [--deep] [--dry-run]` | Makes the index match the disk: quarantines orphans, marks missing or corrupt audio (`--deep` re-hashes), sweeps temp files, holds a free-space floor. |
| `healing schedule install\|remove\|show\|run` | The launchd job that runs collect, prune, clean and then `healing watch` every 6 hours. |
| `healing sets build-general` | Builds the fixed general regression set: 300 LibriSpeech test-other and 200 AMI IHM utterances, seeded and SHA-pinned. A second run prints `unchanged`; a different set is refused. |
| `healing sets fetch-librispeech [--dest DIR]` | Downloads LibriSpeech train-clean-100 (the replay source for `train prepare`): Hugging Face's `openslr/librispeech_asr` `clean/train.100` parquet, 14 shards, 6.43 GB, at the revision the general set pins, each shard pinned by size and SHA-256. Writes `$HEALING_HOME/cache/librispeech-train-clean-100/<NNNN>.parquet`, through `<NNNN>.parquet.partial` that a rerun resumes with an HTTP range; a shard takes its name only once its hash checks, and a mismatch is refused and the partial removed. Checks free space first. With `--dest` (`~` expanded and resolved once), the shards go there and the cache path becomes a symlink to it; a real file or folder already there, a dest inside the cache path, a symlinked `.partial`, and any `*.parquet` that is not a pinned shard (AppleDouble `._*` aside) are refused before anything downloads. A dest that already reaches the cache's target writes there without relinking. A complete, verified folder prints `unchanged`. |
| `healing eval baseline [--model <gguf>]` | An alias of `healing eval --model <gguf> --sets general --vocabulary none` (one eval path) that writes `healing/eval/baseline.json` with the per-source WER. |
| `healing stats paired <a.jsonl> <b.jsonl>` | Δ WER (b − a) with a paired-bootstrap 95% CI, clips as the resampling unit. Takes benchmark JSONL or `nemo_wer.py` output. |
| `healing label corrections [--since] [--recompute]` | Aligns each edited clip's `edited_text` with `final_text`, maps edits back onto `raw_text`, and classifies them `acoustic` (sounds alike), `rewrite` or `unmapped`. Acoustic edits make `reference_text` (your typed words in the raw text) and `edited_positions`; the label then comes from `label all`, which `label corrections` runs after classifying (the one label writer). Skips clips an OpenCode rewrite produced. |
| `healing label all [--json]` | Classifies any unclassified correction, then recomputes every clip's label and weight from corrections and reviews: `strong` and `verified` 1.0, `weak` 0.2 (left out of training unless asked), `unlabelled` 0. The classifier's output (`acoustic_reference`, `edited_positions`) is never overwritten by labels; `reference_text` is derived from the label. Idempotent and a pure function of the evidence (run twice, nothing changes, `classified_at_ms` included): a clip with both acoustic and unmapped edits stays `unlabelled`, a `verified` clip is lowered only by rejecting it (which also clears its reference). |
| `healing review [--n 20] [--strategy random\|uncertain] [--since-cutoff]` | Plays clips with `afplay` and shows the text: Enter accepts, typing replaces, `r` rejects, `p` replays, `q` stops. Each answer is saved at once. `random` feeds the gating sets; `uncertain` (newest weak clips) feeds training only. `--since-cutoff` samples only sessions after the cut-off (the last 14 days), for the rolling set. A random review skips clips already reviewed at random or rejected (uncertain reviews don't shrink its frame) and clips in a cluster that golden, the general set or a recorded train snapshot holds. `--cutoff 14d\|<date>` overrides the window, as for `split build`. |
| `healing vocab mine [--min-pairs 2] [--window 30d] [--train-only] [--json]` | Corrections you made the same way at least twice (`raw_from → to` on normalized words, strong clips' acoustic edits, one count per dictation) become candidate vocabulary terms, ranked by the term's use in the window with a 14-day half-life, then pairs, then recency. Prints `Kit ← kip ×3`, its counts and last-seen date; writes the ranking to `vocab_candidates` (the latest run only). A spelling with two recurring targets gets neither; a common word (`healing/vocab/common_words.txt`) needs 4 pairs; terms and spellings obey Hex's 64-character and 16-spelling limits. `--train-only` counts only clips a training run may take (the A/B needs it). Reads the dataset after a `label all`; never touches Hex. |
| `healing vocab apply [--dry-run] [--max-biased 64] [--force] [--hex PATH]`, `healing vocab revert` | Writes your terms first (in their order), then the saved mined candidates by rank, up to Hex's 500, with one `hex vocabulary set --file`; a second apply writes nothing. At a `normal` or `strong` boost it refuses (exit 4, printing `hex settings set vocabulary_boost light`) unless the latest `healing vocab ab` passed at that same boost on a set of mined terms (the mined terms it biased, term and spellings, stored in `$HEALING_HOME/vocab/ab-verdict.json`) holding every mined term that will sit inside Hex's 64-entry bias cap after the write (terms past the cap need none; a subset is fine); `light` and `off` need none; `--force` overrides and is logged to `vocab/apply.log`. A `set` Hex confirmably refused (a known error code such as `invalid-vocabulary`, or not running) restores the journal; a timeout, a `transport` error, unreadable output or a signal keep `pending`. Holds the healing lock, so a second writer exits 1. Ownership is by content (`$HEALING_HOME/vocab/applied.json`): a mined term you edited is yours, one you removed is never re-added. Reports how many mined terms are biased globally and per mode. Needs a running Hex (exit 3). `revert` removes what healing still owns, in one write. |
| `healing vocab ab [--boost normal] [--model GGUF] [--parent current] [--hex PATH]` | Scores the current GGUF on rolling and general with your vocabulary alone, then with the terms mined from training clips only (in memory, never saved) after it. Prints the term error rate with an exact McNemar test over clips (a clip is right when all its terms are), WER deltas with paired-bootstrap CIs, and the false-replacement rate; writes `$HEALING_HOME/evals/vocab-ab-<ts>.json`. Fewer than 20 term clips is n/a, never a win. Records its verdict, specific to the boost it measured, in `vocab/ab-verdict.json` for `apply`. The M4 gate: general WER CI upper bound at most +0.3 pt, false replacements at most 0.5%, McNemar favouring the mined list; otherwise apply at `light`. Needs a running Hex and a hex with `--vocabulary` (T3.4). |
| `healing split build [--parent current] [--cutoff 14d]` | Recomputes split-clusters (union-find on `reference_text`), then the parent's rolling set (random-verified clips of sessions after the cut-off) and edited-span diagnostic (strong clips of those sessions), each through the same `Zones` predicates `verify` re-asks. A clip may sit in two parents' rolling sets (each model version has its own holdout). Labels clips first (`label all`). Writes owner-only manifests under `$HEALING_HOME/sets/` and registers the general set. For parent `current` the cut-off slides (the last 14 days at each build, D-40); `--cutoff` overrides it. The window is a test zone (D-41). A build makes no train rows; it prints how many trainable clips are outside the test zone as a preview. Training takes its clips with `splits.snapshot_train` (live data; it returns the ids and records a frozen train row of exactly those clips, with the model and a note), not `labels.trainable`, which still holds test clips. |
| `healing split verify` | Exit 1 on any violation: a rolling or edited clip sharing a cluster with golden or the general set, a rolling clip before the cut-off or not random-verified, a gating reference from a weak or strong label, a golden set that no longer matches its pin, a model that trained on a clip a test set now holds (reported as a `snapshot overlap`, checked from each snapshot's own stored texts; an edited set is judged by what it pinned), a set whose sidecar (`clips.jsonl`, with each WAV's hash) changed since it was pinned. |
| `healing golden review [--n 20]` | Confirms random clips (one per cluster, spread over apps and months) into the golden set. At 200 it freezes: manifest and sidecar pinned in `sets/golden-v1/manifest.sha256` and the registry, and the dataset refuses any later change. A freeze that fails is retried by the next run. |
| `healing eval --model <gguf> [--model <gguf> ...] [--sets rolling,golden,general,edited] [--parent current] [--runs 1] [--vocabulary current\|none]` | Scores each model with `hex benchmark-transcription`, interleaved per set, and writes `$HEALING_HOME/evals/<id>.json` with per-clip records. Prints WER, formatting error, term error and edited-span error. A missing set, or a latest split with no clips, prints n/a; the edited set has no WER or formatting error (strong clips are scored only at the words you corrected). `--vocabulary current` passes your saved Hex vocabulary (needs the T3.4 `hex`; use `none` until then). |
| `healing models register-base [--gguf] [--model-id] [--arch] [--scores <json>] [--hex PATH]` | Records Hex's selected catalog model (`hex model list --json`; its file in Hex's `models/`) as v0, current, **pinned by the GGUF's SHA-256**, and copies the GGUF into `$HEALING_HOME/registry/objects/<aa>/<sha>`. Scores come from `--scores` (a `baseline.json`, a `healing eval` document or `{set: {wer}}`), else from `healing/eval/baseline.json` and `$HEALING_HOME/evals/` for that exact file. A second run with the same file is a no-op; a different file is refused (v0 never moves). Run again after a crash, it finishes the interrupted init. |
| `healing models register --gguf --delta --config <yaml> [--parent current] [--train <split> \| --snapshot <sha>] [--converter-repo --converter-rev --export-command --converter-dir] [--scores <json>]` | Records a candidate: base, parent, arch, the training config and its hash, the healing and Hex SHAs, the converter (inherited from the parent unless named; D-43), and the GGUF and LoRA delta as objects. `--train` takes a frozen train row (`splits.snapshot_train`, D-41) and writes its snapshot: sorted `[clip_id, audio_sha256, reference_text_sha256, weight]` lines, `registry/snapshots/<sha>.jsonl.gz` (D-42), using the weights and references the train row froze (D-44). |
| `healing models list [--json]`, `healing models show <v>` | Every version with its state (`candidate`, `promoted`, `rejected`, `rolled_back`), parent, GGUF hash (`·` when retention dropped the file) and general, golden and rolling WER; `show` prints the whole record, the `custom-<16 hex>` id Hex gives its GGUF, which artifacts are kept, and `reproducible` (`partial` once any snapshot audio is gone). GGUFs stay only for v0, current, the previous two promoted versions and undecided candidates; each one dropped appends `pruned_artifact`. Metadata, snapshots and LoRA deltas stay forever. |
| `healing models restore <v> [--converter-dir PATH]` | Rebuilds the GGUF from the base and the LoRA delta with the recorded export command, in a converter checkout at exactly the recorded rev, then checks the SHA-256. A non-deterministic converter's rebuild is kept only when its golden and general WER are within 0.1 pt of the record, and the version records that parity was used. It refuses to start while a promote or rollback runs (and they refuse while it runs). Only recorded scores measured with no vocabulary and on a set whose manifest hash matches count. |
| `healing models current [--hex PATH]` | The current version, cross-checked with the model Hex really runs (`hex status --json`'s `model`: the saved id, or the `fallback` Hex runs while a saved import is missing or changed), as `custom-` + the GGUF hash's first 16 hex or v0's catalog id with its file unchanged. Exit 1 on a mismatch, which it reports and never fixes; 4 when it can't be checked (the saved model isn't installed, or v0's catalog file can't be hashed); 3 when Hex isn't running. |
| `healing models pin-golden` | Pins the frozen golden set's manifest hash in the registry (`golden_frozen`, written once; a different hash is refused, G-10). `golden review` pins on freeze, and `split verify` fails when the golden set no longer matches the pin. |
| `healing gate <v> [--against current] [--eval <json>] [--hex PATH]` | The promotion gate (T7.1, D-12, D-54). Scores the candidate and the version it would replace (plus v0 when it is neither) with `healing eval` and your Hex vocabulary on the candidate's parent's rolling set, golden and general, then prints every check with its estimate, 95% paired-bootstrap interval and threshold: `evidence` (rolling ≥ 1,500 reference words and ≥ 20 term clips), `rolling_wer` (upper bound < 0), `terms` (exact McNemar, p < 0.05), `general_wer`, `golden_wer` and `formatting` (upper bound < +0.5 pt; golden `skipped` until it freezes), `drift_guard` (general WER ≤ v0 + 1.0 pt) and `streaming` (Hex would stream it, asked of the running Hex, and p95 time to text on long clips ≤ current + 50 ms). Margins, resamples and seed live in `healing/gate.toml`, whose SHA-256 each `gate` registry event records. Exit 0 on a pass; 7 on a fail, which also rejects the candidate, or on thin evidence, which leaves it a candidate. The edited-span error is printed but never gates. `--eval` re-judges a saved eval, only one scored with the vocabulary Hex runs now and with each model prepared as the gate would; an eval without golden is refused once golden is pinned, and long clips missing from it fail `streaming`. |
| `healing promote <v> [--hex PATH]` | Ships a candidate whose latest gate passed against the current version on the GGUFs the registry holds now (D-55; otherwise exit 8): `hex model import` of its registry GGUF as "Hex healing v<n>" (skipped when Hex has it; no `--language`), `hex model use custom-<16 hex>`, then waits up to 60 s for `hex status --json` to report it installed with nothing preparing and no fallback, and for `hex model list --json` to say it streams (D-56). Appends `promoted` (with the exact GGUF hash Hex was switched to) and makes it current, then removes the imports healing created (`hex_import` events) except current's, the previous two's and v0's; your own imports, even of the same file, and found Hugging Face models are never touched (D-57). Exit 2 when Hex isn't running (nothing changes), 10 when it must stream and Labs › Stream imported models is off (nothing changes), 9 when Hex doesn't confirm: Hex is switched back, `promote_failed` is appended and the version stays a candidate. A failure returns Hex to the model it ran (its fallback, when it ran one). One promote, rollback or `models restore` runs at a time. Your vocabulary and settings are untouched. |
| `healing rollback [--to <v>] [--reason <text>] [--hex PATH]` | Switches Hex to the previous promoted version (or `--to`), re-importing it from the registry when Hex no longer has it, and appends `rolled_back` with the reason (default `manual`) once `hex status` confirms within 60 s. Exit 2 when Hex isn't running, 9 when it doesn't confirm: Hex is switched back to the model it ran and nothing is recorded. `hex model use <catalog id>` remains the manual escape hatch. A rolled-back version is never promoted again (D-60). |
| `healing watch [--dry-run] [--hex PATH]` | The automatic rollback (T7.3, D-19, D-58, D-59). Watches the current version's promotion: waits (`waiting: 600/1500 words, day 3/14`) until clips you dictated after the promotion and verified in a `random` review hold 1,500 reference words, or 14 days pass. Then it scores the promoted and the previous version on exactly those clips (one `healing eval` with your Hex vocabulary, each model prepared as Hex runs it; clips in a split-cluster any training snapshot holds are left out; a pruned previous GGUF is restored first) and decides once per promotion, recorded as a `watch` registry event with Δ, its interval, words, days and the eval id: `rolled back v<n> → v<m>: Δ +2.1 [+0.8, +3.4]` (through `healing rollback`) only when the one-sided 95% lower bound of Δ WER (promoted − previous; shown as the 90% two-sided interval) is above 0, or formatting's lower bound is above the gate's +0.5 pt, or streaming regressed; otherwise `kept v<n>: Δ +0.2 [−0.9, +1.3]`. Under 1,500 words after 14 days it reports `insufficient evidence, kept` and never rolls back. When Hex runs a model you picked by hand it does nothing and warns (exit 11); after a rollback nothing is watched until the next promotion. Exit 2 when Hex isn't running, 9 when Hex doesn't confirm the rollback (nothing recorded; the next run tries again). `--dry-run` says what it would do and changes nothing. The collect job runs it. |
| `healing train prepare [--include-weak] [--replay 0.2] [--parent current] [--seed 13] [--replay-source DIR]` | Takes a frozen train snapshot (`splits.record_train`) and writes `$HEALING_HOME/train/<train split>/{manifest.jsonl, audio/*.wav, bundle.sha256}`: NeMo `{audio_filepath, duration, text, weight}` lines with the texts and weights the snapshot froze, each storage cluster capped at an effective weight of 3, clips over 30 s cut at pauses (text split by the v0 model's transcripts) or skipped, every clip padded as Hex padded it, and 20% of the sampler's weight self-distilled replay: LibriSpeech train-clean-100 clips labelled with v0's own transcripts, cached by v0's SHA-256 (D-25, D-45). Prints the bundle path and its sha256, which `models register --train` records. Replay reads parquet shards already on disk (default `$HEALING_HOME/cache/librispeech-train-clean-100`, filled by `sets fetch-librispeech`) and never downloads; `--replay 0` trains without. An entry in a test split-cluster fails the run. Needs v0 (`models register-base`) for replay or long clips. |
| `healing report observation [--json]` | Per app: pastes the lab saw, how many were observed, the `span_not_found` rate and the edited rate. |
| `healing protocol corrections plan\|run\|score` | The seeded edit-recall protocol (X-3). `plan` writes `RUNBOOK.md`; `run` needs a person at a Mac. |

## M0 spikes

`spikes/m0/` holds the feasibility spikes and their [report](spikes/m0/REPORT.md).
`roundtrip.sh <unified|tdt-v2>` runs the whole shipping path: base control, LoRA fine-tune,
conversion, Q8_0, `hex model import` and scoring. It needs a
[transcribe.cpp](https://github.com/anomalyco/transcribe.cpp) checkout (`$TRANSCRIBE_CPP`), whose
pinned Parakeet environment provides NeMo (D-29). Expect about 25 minutes and 10 GB of disk on an
M4.
