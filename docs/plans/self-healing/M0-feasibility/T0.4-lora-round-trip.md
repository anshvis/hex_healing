# T0.4 - LoRA fine-tune → merge → GGUF → Q8_0 → `hex model import` round trip

## Milestone
M0 - Feasibility spikes and baseline. **Covers:** AC-2, X-1. **Surface:** backend (scripts and CLI runs only).

## Branch
`healing/m0-feasibility`, base `dev`. One PR for M0. No tickets (D-1).

## Objective
Prove, with one rerunnable script, that a LoRA-merged fine-tune of the chosen Parakeet architecture survives the whole shipping path:
1. NeMo export.
2. transcribe.cpp conversion to GGUF.
3. Q8_0 quantization.
4. `hex model import`.
5. Transcription in Hex's own runtime.

The fine-tune's learned change must still show after quantization.

## Context
Shipping a model (brief, step 7) is the fragile step.
- Hex pins transcribe.cpp at `anomalyco/transcribe.cpp@bcb639fa` (`Cargo.toml:46-54`). The Parakeet converter that made the catalog GGUFs is at transcribe.cpp `7045d1c` (`src/transcription/artifacts.rs:145-165`).
- Imports accept F32, F16 and Q8_0 parakeet GGUFs. The header must carry `stt.variant` and `general.languages` (`src/transcription/custom_models.rs:567-640`, `src/transcription/gguf_header.rs:23`).
- Orukeet (`artifacts.rs:42-50`) is proof that one fine-tune made it through this path.

Unknowns:
- whether the converter accepts a checkpoint whose weights were changed by merging LoRA;
- whether a small LoRA delta survives Q8_0;
- which base (Unified or TDT v2) has a public NeMo checkpoint (D-13).

## API
Source: inferred.
### `healing/spikes/m0/roundtrip.sh <base: unified|tdt-v2>`
- **Inputs:** the env `SPIKE_DIR` (default a mktemp dir) and `TRANSCRIBE_CPP_REV` (default `7045d1c`).
- **Output:** exit code 0 or 1, plus `REPORT.md` with one row per step (command, exit, duration, artifact SHA-256).
- **Steps:**
  1. Fetch the base `.nemo` from Hugging Face (`nvidia/parakeet-tdt-0.6b-v2`, or the Unified checkpoint if public).
  2. Make 30 `say`-voice clips that use the nonsense word "Qorvyx" (D-27; the packet first named "Qorvyx", which the base already transcribes) in sentences. 20 are for training and 10 are held out. Use 16 kHz WAV.
  3. Train LoRA (rank 16; encoder linears plus the TDT predictor and joint, D-14) for at most 200 steps (`healing/spikes/m0/lora_tiny.py`). Use CPU. NeMo's TDT loss is unreliable on MPS, so don't use MPS. If CPU is too slow (over 1 h), use a single Modal run on synthetic clips only; G-3 holds because no personal data is involved.
  4. Merge into the base and save `merged.nemo`.
  5. Convert with transcribe.cpp's Parakeet converter at `TRANSCRIBE_CPP_REV`. Then run `transcribe-quantize … q8_0`.
  6. Run `HEX_APPLICATION_SUPPORT_DIR=$SPIKE_DIR/hex cargo run --release -- model import model-q8_0.gguf --name spike`.
  7. Run `cargo run --release -- benchmark-transcription` on T0.3's 300 LibriSpeech clips plus the 10 held-out Qorvyx clips (group `target`, `vocabulary: ["Qorvyx"]`, `expected_terms: ["Qorvyx"]`), with the tuned Q8_0 GGUF and with T0.1's base GGUF.
  8. Run NeMo `transcribe()` on the same clips with `merged.nemo`.
  9. Report the per-tensor ‖ΔW‖ (merged − base) against the Q8_0 rounding step (block scale / 127) for every LoRA-touched tensor. Report the share of the delta that survives quantization: ‖Q(merged) − Q(base)‖ / ‖ΔW‖.
- **Errors:** any step's non-zero exit stops the script and records the step and its stderr tail in REPORT.md.
- **Side effects:** temp files only; the network is used only for the Hugging Face and git fetches.
- **Idempotency:** re-runnable, because it starts from a fresh `SPIKE_DIR`.

## Decisions
- Which base? Try Unified first (Hex's default, D-13). If its NeMo checkpoint isn't public or doesn't convert, use TDT v2. Record both attempts.
- Train on CPU or MPS, not a rented GPU? Yes. 200 steps of rank-16 LoRA on 20 short clips is enough to move one word, and it needs no credentials (X-6 doesn't apply).
- Does WER parity compare NeMo on F32 against GGUF on Q8_0? Yes, because that is the real shipping comparison. The tolerance is a ±1.0 pt paired CI on 300 clips. Ten clips is about 80 words, too few to resolve 1 pt.
- Does the spike's large delta prove a real round's small delta survives? No. The ‖ΔW‖ against Q8_0-step table is the evidence for that, and every real round's gate (T7.1) scores the Q8_0 file anyway.

## Watch out for
- **Converter header fields.** Imports refuse a GGUF without `stt.variant` or `general.languages`. Check that the converter writes them for a merged checkpoint, which may lack the original model card metadata.
- **LoRA module names after merge** must match the base's tensor names exactly, or the converter will skip or reject them. Diff the tensor name lists of the base and merged GGUFs; they must be identical.
- **Q8_0 hiding the delta.** The check that the target word changes runs on the Q8_0 file, not on F16.
- **Nonsense word too easy.** The target word must not already transcribe correctly with the base model. Assert that the base gets it wrong first.
- **Disk.** Each 0.6B `.nemo` is about 2.4 GB and each GGUF about 0.7 GB. Use the internal disk, not the exFAT T5.
- **`hex model import`** must use an isolated `HEX_APPLICATION_SUPPORT_DIR`. Never touch the real `~/Library/Application Support/hex`.
