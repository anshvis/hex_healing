# T0.2 - Prove the kept recording is the model's input

## Milestone
M0 - Feasibility spikes and baseline. **Covers:** AC-1, X-2. **Surface:** backend (a Rust test and a CLI run).

## Branch
`healing/m0-feasibility`, base `dev`.

## Objective
Prove that `history-audio/<id>.wav` holds the exact samples Hex's whole-clip transcription received, up to i16 quantization. Lock this in with a test, so training data can never silently drift from what the model heard.

## Context
In `src/parakeet.rs:458-464`, both the kept recording and the inference read the same buffer:
1. `let samples = clip.into_transcription_samples();`
2. `crate::dictation::diagnostics::persist(&samples)`
3. `Recording::keep(&samples)`
4. `engine.finish_with(stream, samples, offline)`

`Recording::keep` returns nothing unless Labs › Keep recordings is on (`src/history/recordings.rs:38`). The WAV is 16 kHz mono 16-bit (`:70-90`). The live stream sees pause-trimmed audio (AGENTS.md: pauses are cut to 2.5 s plus 0.3 s), but the final text is either the stream's or the whole clip's. The kept recording is the whole clip.

Consequence for training: when the stream's text is used, its input differed only in trimmed long pauses. That doesn't affect labels.

Open: does the same hold for Linux and Windows dictation (`dictation/modes`, `transcription/local_transcriber`)? This spike checks macOS and records the other OSes' callers.

## Domain model
Source: inferred. No change.
- **`history-audio/<id>.wav`.** Role: one dictation's audio. RIFF, PCM 16-bit, 16 kHz, mono. The name is the History entry id. It exists only if the entry's `recording_bytes > 0`.

## Files to change
- `src/history/recordings.rs` (`#[cfg(test)]`): add `kept_wav_round_trips_samples_to_i16`. Write a known f32 buffer and read the WAV back. Every sample must equal `(x * 32767).round()` clamped; match the code's own quantization rule exactly.
- `src/parakeet.rs` (`#[cfg(test)]`, if the code shape allows it without new seams): assert that the recording handed to `InferenceJob` and the samples passed to the engine are the same buffer. If that needs a new seam, skip it and rely on the live check below (no hypothetical seams, AGENTS.md).
- `healing/spikes/m0/recording_fidelity.sh`: a live smoke check only. The diagnostic and History WAVs are both written from the same `samples` variable (`src/parakeet.rs:461-464`), so comparing them is circular. It proves the writers agree, not that the model heard those samples.
- `src/parakeet.rs` or `src/transcription/engine.rs` (`#[cfg(test)]`): the real proof is at the `finish_with` boundary. Assert that the samples `engine.finish_with` passes to the offline closure and to the stream's finish equal the `Recording` buffer. Use the existing engine test doubles if they exist; if that needs a new seam, record the code-reading argument in REPORT.md instead.
- `healing/spikes/m0/REPORT.md`: append the result.

## Gold-star references

## Decisions
- How to drive a real dictation without a microphone? Use `HEX_AUDIO_FIXTURE=<wav>` (real capture pipeline, AGENTS.md `audio/fixture`). Then `hex dictation start`, wait 3 s, `hex dictation stop`, with `HEX_APPLICATION_SUPPORT_DIR` isolated and `labs.keep_recordings` on through `hex settings set`.

## Watch out for
- The fixture loops from its start at each open, and pre-roll adds 450 ms of earlier audio. So compare the History WAV with the diagnostic WAV of the same capture, not with the fixture file.
- Quantization: compare as i16. The diagnostic file may be f32; convert with the same rule.
- An empty capture (`samples.is_empty()`) keeps nothing. Use a 3 s or longer fixture with speech so the silence discard doesn't drop it.

## Acceptance criteria
- **AC-1** The kept recording equals the buffer handed to `finish_with`, by test or by a recorded code reading if a seam would be needed. The WAV round trip matches i16 quantization. REPORT.md records which source produced the final text, the stream or the whole clip. For Unified it is often the stream, which saw audio with long pauses trimmed (2.5 s + 0.3 s). That is harmless for labels, but training uses the whole clip.
