# T0.1 - Base conversion control and the parity harness

## Milestone
M0 - Feasibility spikes and baseline. **Covers:** AC-2 (control half), X-1. **Surface:** backend (scripts and CLI runs only).

## Branch
`healing/m0-feasibility`, base `dev`. One PR for M0. No tickets (D-1).

## Objective
Convert the **untouched** base NeMo checkpoint with transcribe.cpp's converter and quantize it to Q8_0. Then show that Hex's runtime matches NeMo on 300 LibriSpeech clips: the paired-bootstrap 95% CI of the WER difference lies within ±1.0 pt.

This separates "the converter or decoder differs" from "the fine-tune broke" before T0.4 adds LoRA. It also builds the paired-bootstrap tool that every later gate reuses.

## Decisions
- NeMo's WER is normalized with the benchmark's own rule (split on non-alphanumerics, lowercase; `benchmark.rs:505`), so the two sides compare like with like.
- Both bases are tried. REPORT.md records the one that passes, and T0.4 uses it.

## Watch out for
- **Decoder differences.** NeMo's TDT greedy decode and transcribe.cpp's may differ slightly. That is exactly what the ±1.0 pt CI tolerates. A larger gap means X-1.
- **Disk.** Each `.nemo` is about 2.4 GB. Use the internal disk.
- **Isolation.** The import uses an isolated `HEX_APPLICATION_SUPPORT_DIR`.

## Acceptance criteria
- **AC-2 (control):** for at least one base, the converted Q8_0 GGUF imports and the parity CI is ⊂ [−1.0, 1.0] on 300 clips. `healing stats paired` reproduces a hand-computed CI on a fixture.
