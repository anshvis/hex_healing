# T3.3 - `healing eval <gguf>`: WER and term error rate on each set

## Milestone
M3. **Covers:** AC-9. **Surface:** backend.

## Branch
`healing/m3-labels-eval`.

## Objective
One command scores one or more GGUFs on rolling, golden and general, using `hex benchmark-transcription`, in the same run and on the same machine. It writes a scores JSON that the registry (M5) and gate (M7) consume.

## Context
- `hex benchmark-transcription <manifest> --model <gguf>` returns a `summary` with `wer` and `quality.term_recall` (`src/transcription/benchmark.rs:222-361`). It runs on Metal (`src/parakeet.rs:1316`).
- Term error rate is defined as `1 − term_recall` over the `expected_terms` of clips that have terms.
- **Formatting error rate:** WER computed in `healing` on case- and punctuation-preserving tokens, from each clip's `transcript` (`benchmark.rs:317`). The benchmark's own WER strips both (`:505`), so it can't see a model that forgot punctuation (challenge finding 12).
- **Edited-span error rate:** for each strong clip, whether the candidate's transcript at the edited positions matches the corrected words, aligned against `reference_text`.
- **Vocabulary:** eval passes your current global vocabulary through `--vocabulary` (T3.4), so scores reflect what you actually run (challenge finding 14).
- Extended from T0.3's `bench.py`.

## Domain model
Source: inferred.
- **`$HEALING_HOME/evals/<eval_id>.json`.** Fields:
  - `eval_id`
  - `hex_sha`
  - `models[]`, each `{gguf_path, gguf_sha256}`
  - `sets[]`, each `{split_id, manifest_sha256, n}`
  - `scores[model][set]`, each `{wer, word_errors, ref_words, format_error_rate, term_error_rate, term_hits[], median_rtf, p95_clip_ms}`
  - `per_clip[model][set]`: `[{id, word_errors, reference_words, format_errors, format_words, terms_hit, transcript}]`, which feeds the paired bootstrap and McNemar tests (T0.1's `healing stats`, T7.1)
  - `edited_span[model]`: `{errors, positions}` on the strong diagnostic clips
  - `started_at_ms`, `duration_ms`

## API
- **`healing eval --model <gguf> [--model <gguf> …] [--sets rolling,golden,general,edited] [--runs 1] [--vocabulary current|none]`**
  - Prints a table and writes the eval JSON.
  - Errors:
    - a missing set prints n/a and continues;
    - a benchmark failure is non-zero and names the model and set.
  - Models are run interleaved per set (A, B, A, B), so thermal drift is shared.

## Decisions
- Always score candidate and current together; never compare with a stored number (see "Why a rolling holdout?").
- One run per set by default. WER is deterministic for a fixed model and audio; extra runs only measure speed.

## Watch out for
- **The benchmark's text normalization** must be the same for all models. It is the same binary.
- **A GGUF path outside Hex's models folder:** confirmed by T0.1, or by T0.3's exit.
- **Long runs:** 700+ clips × 2 models takes minutes. Show progress.

## Acceptance criteria
- **AC-9:** `healing eval --model base.gguf --model tuned.gguf` (T0.4's spike files) writes an eval JSON with both models × the available sets, including the per-clip records, the formatting error rate and the edited-span error rate. Its general-set WER for the shipped model equals T0.3's baseline within 0.2 pt. A transcript with its punctuation stripped raises the formatting error rate but not the WER (a fixture test).
