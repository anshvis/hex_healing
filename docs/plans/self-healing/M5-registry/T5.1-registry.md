# T5.1 - `versions.jsonl`, content-addressed artifacts, snapshot hashing, restore

## Milestone
M5. **Covers:** AC-11, G-10. **Surface:** backend.

## Branch
`healing/m5-registry`, base `dev`.

## Objective
An append-only registry where each version records:
- base, parent and dataset snapshot;
- training config, code SHA and converter revision;
- artifacts by SHA-256;
- scores and gate decision;
- state.

It supports `list`, `show`, `restore`, and pinning the golden set's hash.

## Domain model
Source: inferred.

### `$HEALING_HOME/registry/versions.jsonl`
Append-only. Each line is an event: `{event: registered | scored | promoted | rejected | rolled_back | pruned_artifact, version, at_ms, …}`. Current state = fold the events.

### Version record (from `registered`)
- `version`: `v<n>`.
- `base`: the catalog id and its GGUF sha256.
- `parent`: a version or null.
- `arch`: `parakeet-unified` or `tdt-v2` (from T0.1).
- `dataset`:
  - `snapshot_sha256`: the hash of the sorted `(clip_id, audio_sha256, reference_text_sha256, weight)` lines;
  - `snapshot_path`: `registry/snapshots/<sha>.jsonl.zst`, ids and hashes only, no audio, no text;
  - `train_n`, `strong_n`, `weak_n`.
- `config`: the training config (YAML text) and its sha256.
- `code_sha`: `healing` and Hex git SHAs.
- `converter`: `{repo, rev}`.
- `quantization`: `q8_0`.
- `artifacts`: `{lora_delta: sha, merged_nemo: sha|null, gguf: sha}`, stored in `registry/objects/<aa>/<sha>`.

### State
`candidate`, then either `promoted` or `rejected(reason)`. A promoted version can later be `rolled_back(reason)`. Exactly one version is `current`.

### Golden pin
`{event:"golden_frozen", sha256, n}`. It is written once. A second one with a different hash is refused (G-10).

### Retention
- Keep forever: metadata, snapshots, LoRA deltas.
- Keep the GGUF only for `current`, the previous 2 promoted versions, and v0.
- `merged_nemo` is dropped after export.
- Deleting an object appends `pruned_artifact`.

## API
- **`healing models register-base`:** creates v0 from Hex's current catalog model, **pinned by the GGUF's SHA-256**, not its catalog id. A Hex catalog update that changes the file therefore can't silently move v0 and the drift anchor (challenge finding 20). v0's GGUF is copied into `registry/objects/`.
- **`healing models register --gguf <path> --delta <path> --config <yaml> --snapshot <sha> --parent <v>`:** creates a candidate.
- **`healing models list | show <v>`.**
- **`healing models restore <v>`:** rebuilds the GGUF from base + delta via the T6.3 export with the recorded converter rev, then checks the SHA-256. If the converter isn't deterministic, it checks WER parity on the golden or general set within 0.1 pt, and records that parity was used.
- **`healing models current`:** the version whose GGUF Hex runs, cross-checked against `hex model list` (the selected `custom-<16hex>` must equal the recorded gguf sha prefix).

## Decisions
- JSONL event log rather than SQLite. It's human-readable, append-only and diffable, and the volume is tiny.
- Snapshots hold ids and hashes, not audio. A version is reproducible only while its audio is in the dataset. Protected (strong) clips are never evicted, so strong-only snapshots stay reproducible. Weak clips may not be; record `reproducible: partial` when any snapshot audio is gone.

## Watch out for
- **A crash mid-append:** each line is written whole with fsync. A torn last line is ignored on read.
- **Hex's selected model changed by hand** (you picked another model). `current` reports a mismatch. Never "fix" it automatically.
- **Disk:** report object bytes in `healing status`.
