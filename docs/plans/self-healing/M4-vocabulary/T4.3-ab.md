# T4.3 - `healing vocab ab`: the Tier 1 A/B

## Milestone
M4. **Covers:** AC-10 (proof of effect). **Surface:** backend.

## Branch
`healing/m4-vocabulary`.

## Objective
Measure whether mined vocabulary helps, using T3.4's `--vocabulary` flag. Score the current GGUF with and without the mined terms, on rolling and general. Report:
- the term error rate delta, with an exact McNemar test on per-clip term hits;
- the WER delta, with a paired bootstrap CI;
- the false-replacement rate.

## Context
- T3.4 adds `hex benchmark-transcription --vocabulary`.
- T0.1 adds `healing stats paired`.
- Mining must use `--train-only` so terms learned from rolling clips don't leak into the measurement (T3.2).

## API
- **`healing vocab ab [--boost light|normal|strong]`:**
  1. Mine with `--train-only`.
  2. Build two vocabulary files: yours only, and yours plus the mined terms in apply order (T4.2).
  3. Run eval twice.
  4. Print the deltas and CIs.
  5. Write `$HEALING_HOME/evals/vocab-ab-<ts>.json`.

## Files to change
- `healing/healing/vocab/ab.py`, `healing/healing/cli.py`, `healing/tests/test_vocab_ab.py`

## Decisions
- The pass bar for shipping mined terms at `normal` boost is the M4 exit gate:
  - general WER CI upper bound ≤ +0.3 pt;
  - false replacements ≤ 0.5%;
  - the term McNemar test favours the mined list.

  Otherwise apply defaults to `light`.

## Watch out for
- **Per-mode vocabularies** take slots first. The A/B uses the global list plus no mode, and notes that it does.
- **Too few term clips** (under 20) → report n/a. Don't call it a win.

## Acceptance criteria
- **AC-10 (effect):** on T0.4's Qorvyx fixture (a mined `Qorvyx ← corvix`), the A/B shows the term hit with the mined list and the miss without. The report includes CIs.

## Guardrails and exit criteria
- **G-3:** offline.
- **G-6:** reads your vocabulary through `hex vocabulary list` only, and never writes it.
- **X-4:** too few term clips to decide is reported as n/a, never as a win.
