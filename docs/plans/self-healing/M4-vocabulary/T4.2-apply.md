# T4.2 - `healing vocab apply`: ranked, ≤64 biased, your terms untouched

## Milestone
M4. **Covers:** AC-10. **Surface:** backend. Hex settings change through its CLI.

## Branch
`healing/m4-vocabulary`.

## Objective
Write the mined terms into Hex's vocabulary so that:
- every term you added by hand stays, and keeps its place before the mined terms;
- mined terms follow in rank order, filling up to 64 biased slots in total;
- mined terms below the cut stay in the stored list (up to 500), so they move up as they're used more.

## Context
- `hex vocabulary list|add <term> [--sounds-like a,b]|remove <term>` goes through the running Hex (`src/control/cli.rs:393-410`, `docs/cli.md:71,240`).
- `add` appends. Biasing takes `entries[..64]` in stored order (`src/dictation/vocabulary.rs:290`).
- A mode's own vocabulary is biased before the global list (`src/dictation/vocabulary.rs:174-198`), so in an app with a mode, fewer than 64 global slots are left.
- Changed after the challenge (finding 21): ordering is written in **one atomic save** with `hex vocabulary set --file` (T4.4), not a run of `add` and `remove` calls that leave a half-written biased set.

## Domain model
Source: inferred.

### `$HEALING_HOME/vocab/applied.json`
- Holds `{applied_at_ms, terms: [{term, sounds_like}], rejected: [term]}`.
- **Ownership is by content:** healing owns a term only while the term **and** its spellings still equal what healing wrote. A term you edited (for example, added a spelling) becomes yours and is never removed or reordered (D-20).

### Hex `settings.json` `vocabulary` (written only through `hex vocabulary`)
- Before: `[ {term:"Anomaly"}, {term:"Rune"} ]` (yours).
- After: `[ Anomaly, Rune, {term:"Kit", sounds_like:["kip"]}, … ]`.

## API
- **`healing vocab apply [--dry-run] [--max-biased 64]`:**
    1. Read `hex vocabulary list --json` (check the flag exists; otherwise parse the text output).
    2. Split it into yours (anything healing doesn't own by content) and healing's.
    3. Build the new list: yours in their current order, then the candidates in rank order. Skip any term you already have (your casing wins), and anything in `rejected`.
    4. Write it with one `hex vocabulary set --file`.
    5. Write `applied.json`.

    It reports per mode how many mined terms are actually biased (64 − mode terms − your terms).
- **`healing vocab revert`:** writes the list minus the terms healing still owns by content, in one `set`.

## Decisions
- D-20: your terms first. If your terms alone take 64 or more slots, no mined term is biased. Warn in `healing status`.
- Gate (T4.3): at a `normal` or `strong` `vocabulary_boost`, apply refuses (exit 4) unless the latest `healing vocab ab` passed at that boost on a mined set holding every term apply is about to add (subset fine; otherwise rerun the A/B); `light`/`off` need none; `--force` overrides, logged. It prints `hex settings set vocabulary_boost light`; healing never writes the setting.
- A refused `set` restores the journal; a timeout keeps `pending` (unioned across retries) until a write is confirmed. The journal and its directory are fsynced before Hex is called, and apply/revert hold the healing lock.
- Is a term you added later, after mined ones, demoted? No. Every apply rebuilds the list with your terms first.

## Watch out for
- **Hex isn't running.** `hex vocabulary` fails. Exit non-zero with "Hex isn't running"; the launchd run just retries next time.
- **A mined term you later remove by hand:** respect it. Record it in `rejected` and never re-add it.
- **A healing-owned term you then edit** (by adding a spelling): it becomes yours; revert must not delete it.
- **`hex vocabulary` is documented as macOS only.** This is fine (D-3).

## Acceptance criteria
- **AC-10 (apply):**
  - starting from your 2 terms, apply gives your 2, then the mined terms in rank order;
  - a second apply is a no-op;
  - revert leaves exactly your 2;
  - a mined term you removed is never re-added;
  - a mined term you edited survives revert;
  - the list is written in exactly one `set` call.

## Guardrails and exit criteria
- **G-6:** writes Hex settings only through `hex vocabulary set`, never by editing `settings.json`.
