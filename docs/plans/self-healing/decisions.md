  - on Return;

A tick that saw a value change reads once, on that tick (40 ms gap, under the 50 ms tick), not once a second. With a 1 s debounce, select "Kip", type "Kit", press Return inside a second kept the half-typed "send it to K". The read can still be one tick behind the typing, which is as close as polling at the watcher's tick gets; it is not "never a keystroke behind". The caret is read before the paste; the first read showing the paste within 8 units of it lands there and the region is snapped to the field's tokens. With no caret the field is read before the paste, and the one new occurrence is adopted. The region is followed by diffing each read against the last (typing before moves it, inside stretches it, after leaves it); a change that crosses an edge, or could as well sit on either side of one, loses it; a change that deletes words at an edge leaves that edge open for the words deleted, no more (see round 7). A blank read or a window retires it, and a lost region stays lost. The invariant is to fail closed: store only text inside the region, never text before or after it, and no edit before the paste was seen whole. Checked by a generated property test (superseded by the round 7 oracle below).

## Models and training
- **D-13** The base architecture is Parakeet Unified English 0.6B (Hex's default) if its NeMo checkpoint is public and survives T0.1's round trip. Otherwise Parakeet TDT 0.6B v2. Nemotron streaming is out of scope (brief: worse when not streaming). *Instead:* v3 (multilingual).
- **D-14** Fine-tuning uses LoRA (rank 16), merged into the weights before conversion. It targets the encoder's attention and feed-forward linear layers, **plus the TDT predictor and joint linears**: new words live partly in the decoder, so encoder-only LoRA may not learn them. NeMo's residual adapters have a nonlinearity, so they can't be merged, and transcribe.cpp loads only plain weights. T0.1 measures the per-tensor ‖ΔW‖ against the Q8_0 rounding step. *Instead:* encoder-only, which forgets less and learns new words less.
- **D-15** The GPU provider is Modal, with RunPod as the fallback. *Instead:* RunPod first.
- **D-18** Retraining starts only with at least 200 new strong clips and at least 7 days since the last run. *Instead:* the clip count alone.

## Promotion
- **D-12** The gate uses paired statistics over clips: 10,000 bootstrap resamples of Δ = Σerrors / Σwords, with clips as the units. A candidate passes only when every check holds:
  - **Rolling:** the 95% CI upper bound of Δ WER is below 0 (a real improvement).
  - **Terms:** an exact McNemar test on per-clip term hits favours the candidate at p < 0.05.
  - **General and golden:** non-inferior, with the CI upper bound of Δ WER under +0.5 pt.
  - **Formatting:** the formatting error rate is non-inferior, CI upper bound under +0.5 pt.
  - **Drift guard:** general WER ≤ v0 + 1.0 pt.
  - **Streaming:** the candidate streams, and p95 time to text ≤ current + 50 ms.
  - **Evidence:** at least 1,500 reference words in rolling and 20 term clips.

  *Instead:* the brief's point margins (0.3 pt / 5%). At these set sizes they are inside the noise. *(Revised after the challenge; the golden set now gates as non-inferiority.)*
- **D-19** Auto-rollback runs after at least 1,500 verified reference words arrive post-promotion, or 14 days, whichever comes first. It rolls back only when the promoted model is significantly **worse** than the previous one: the one-sided 95% CI lower bound of Δ WER is above 0. That is not the superiority test, which would flip-flop under noise. *Instead:* also watch the live edited-span error rate and re-run as soon as it jumps.
- **D-20** Mined terms fill the biased slots only after every term you added by hand. Mode vocabularies take slots first (`src/dictation/vocabulary.rs:174-198`), so slots are counted per mode. Ownership is tracked by content: a term you edited becomes yours. The list is written atomically with a new `hex vocabulary set --file` (T4.4). *Instead:* rank everything together by frequency.

- **D-41** (T3.2 revision, after D-40) The 14-day window is the test zone, and training gets its clips from exactly one function that records them. `splits.snapshot_train(store, include_weak=…, model=…, note=…)` returns the clip ids and writes a frozen `train` row whose members are exactly those clips (weak ones when asked), with the model, the note and each member's texts as its record; `preview_train` is the read-only twin and records nothing. A build is not training and creates no train rows, so there is no unbounded history of builds and no empty rows. What a snapshot may hand out is `Zones.may_train`: no clip of a session inside the window, none sharing a split-cluster with an in-window clip, a registered test set (golden, rolling, edited) or the general set, from live data, so it is right after a review no build has seen. Every cluster of every recorded snapshot is reserved, from the texts it stored when it handed its clips out (they join the clustering as `train:<split>:<clip>` entries, as the general set's references do `general:<id>`), so a clip whose text changes later cannot hide what the model saw: the `rolling`, `golden` and `random_review` frames refuse it, so a clip any model trained on can never be drawn into golden, the random-review frame or rolling or edited eligibility, whichever path it came through. `split verify` re-asks `Zones` of the registered members and checks each recorded snapshot against the test clips' texts directly (its own stored member texts, the near-duplicate test, no union-find, which links non-transitively and could fail verify for good); snapshot overlaps are a true contamination report and print apart from current-build leaks. A clip may sit in more than one parent's rolling set, because parents are model versions and each has its own holdout: the "already a registered member" check applies only to the clip's own parent, while every parent's sets still close the clip to training and `eval` resolves sets for a named `--parent` (default current), never the newest of any parent. A build replaces only its own parent's. `Zones` takes its cut-off at load and exposes the frames `rolling`, `golden` and `random_review` (a random review also skips registered members of any parent), and `build` selects, `golden.add` admits and `verify` re-asks through one `why_not(kind, ...)`; an edited set is judged by the label and positions it pinned, so a correction that changes after the build does not flag a set that is still what was built. Golden adds, snapshots and builds each decide and write in one `BEGIN IMMEDIATE` transaction, so concurrent runs serialize. M5/M6 pin "what a model trained on" to a train row. *Instead:* a train split per build (unbounded, and not what any model took), or excluding only the last build's registered members (a review after the build leaked into train).
- **D-42** (T5.1) Dataset snapshots are stored as `registry/snapshots/<sha>.jsonl.gz`, gzip from the standard library (level 9, no name or time in the header, so the same lines always give the same bytes), not `.jsonl.zst`: `zstandard` is not a `healing` dependency and the files are a few KB of ids and hashes. The snapshot's SHA-256 is over the uncompressed sorted lines, so the compression could change later without changing any recorded hash. *Instead:* add `zstandard` for the spec's `.zst`.
- **D-43** (T5.1) The T6.3 export does not exist yet, so a version records its converter as `{repo, rev, command, checkout}`: `command` is the export argv with `{base}`, `{delta}`, `{config}`, `{output}` and `{checkout}` placeholders, inherited from the parent unless `register` names new ones. `restore` runs it in a checkout that must be at exactly `rev` with no local changes, then checks the SHA-256; on a mismatch it scores the rebuild on the golden and general sets the version has WERs for (sets whose manifest changed are skipped, at least one must compare) and keeps it only within 0.1 pt, appending a `restored` event (`method: sha256 | wer_parity`, the scores, the rebuilt hash, which is then the version's GGUF). The converter and the parity check are function arguments, so T6.3 plugs in without a registry change. Retention also keeps an undecided candidate's GGUF (its gate still needs the file); it goes once rejected. Promote, reject and roll back are functions here with no CLI until M7. *Instead:* block T5.1 on T6.3, or mark determinism in the record up front.
- **D-44** (T5.1, extends D-41) `splits.snapshot_train` also stores each member's weight in the train row's detail (`weights: {clip: weight}`), beside the texts it already froze, and a registry snapshot hashes those stored weights and reference texts, never the clips' live ones. A relabel after training otherwise changed the hash of the same frozen row and recorded weights the model never trained with. - **D-45** (T6.1) How the training bundle weighs and cuts:
  - **Cluster cap.** A storage cluster's effective weight is the sum of its manifest entries' weights (what the sampler sees), scaled down to exactly 3 when over. A long clip cut into pieces counts each piece, so a four-piece clip alone is scaled to 0.75 a piece.
  - **Replay share.** 20% is of the sampler's weight, not of the clip count. The round takes round(W·r/(1−r)) replay clips (W = the user entries' weight), at most the eligible pool, and weighs each so the share is exact. The pool is 2,000 utterances picked once by a fixed seed; base transcripts are made 200 at a time and cached by the v0 GGUF's SHA-256.
  - **Replay and the test sets.** A source holding a general-set clip id is refused. A replay clip whose base transcript shares a split-cluster with a test reference is dropped before mixing (public data, nothing is lost), and the whole manifest is then asserted clean: a user clip in a test cluster still fails the run. v0 is a hash-named registry object, so the benchmark is handed it through a symlink under its catalog file name (`register-base`'s source path, else `<id>-Q8_0.gguf`): Hex recognizes a catalog model by name and size, and only then adds Unified's 400 ms tail, which the training audio gets too.
  - **Long clips.** The pause segmenter's cuts are candidates; the fewest that keep every piece under the cap are used (the latest that fits, piece after piece), because each cut is a text boundary. The text is split by transcribing the pieces with v0 and aligning to the reference; a boundary counts only where every minimum-edit alignment (counted, not one traceback's tie-break) matches the words heard on both sides of the cut to the same adjacent reference words exactly, else the clip is skipped. A piece's own text can match a test reference that the whole clip does not: such a clip is skipped and counted (`over 30 s and a piece is near a test set`), not a failed run, and the final assert checks every entry's own text too.
  - **What the test sets hold** is each member's live texts plus the reference its pinned manifest scores, read only after the set's registered hashes check; a later correction of a test clip cannot reopen its old text to training. A pin that no longer checks fails the run. The 30 s cap includes Hex's padding (a catalog Unified clip may hold 29.6 s of audio).
  - **Padding** follows each clip's own `model_id`, as Hex padded it (the catalog Unified gets the 400 ms tail, an import none: D-39 is still open). Replay is padded as v0.
  - **Offline.** LibriSpeech train-clean-100 is read from parquet shards already on disk; nothing downloads them (fetching belongs in `healing/sets/`, the one place G-3 allows the network).
  - **The bundle** is named after the train row (`splits.record_train`, which `snapshot_train` now wraps). Its sha256 is over `bundle.sha256`, the listing of every file's hash; `audio_filepath` is relative, so a copied bundle hashes the same. `healing models register --train` records it as `dataset.bundle_sha256` (verified, or None when no bundle was prepared). A failed prepare keeps its train row: the snapshot was handed out, and reserving its clusters is the safe side.

  *Instead:* cap clusters by clip count, replay by clip count, skip every clip over 30 s, or download LibriSpeech in `prepare`.
- **D-30** AMI references drop disfluencies dictation never outputs (um, uh, hmm, mm-hmm, uh-huh and the like) and keep real backchannels ("yeah", "oh", "okay"). AMI clips need at least 3 words left. *Instead:* keep fillers, which would add errors no model change can fix.
- **D-39** *Open, for M6/M7.* A fine-tuned Unified English model imported as `TranscriptionModelId::Custom` gets no trailing silence in dictation (`trailing_silence_samples` matches only the catalog's `ParakeetUnifiedEnglish`), and now none in the benchmark either, while the catalog model gets 6,400 samples (#1629). Nothing changes in T3.4; M6/M7 decide whether the A/B pads both the same and whether a Unified import takes the tail. *Instead:* none yet.
