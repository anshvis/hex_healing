# T6.3 - Export: merge → GGUF → Q8_0 → register candidate

## Milestone
M6. **Covers:** AC-12. **Surface:** backend.

## Branch
`healing/m6-training`.

## Objective
`healing export <lora_delta>` does the following:
1. Merges the delta into the base.
2. Converts with transcribe.cpp's converter at the pinned rev from T0.1.
3. Quantizes to Q8_0.
4. Checks the header with `hex model import --dry-run`, if it exists, or with an isolated import.
5. Registers a candidate (T5.1) with its config, snapshot, code SHAs and artifacts.

## Context
T0.4 proved this path once by hand. This makes it the one code path used by both export and `healing models restore`.

## API
- **`healing export <delta> --config <yaml> --snapshot <sha> [--parent <v>]`** → prints the candidate version.
- **Errors:**
  - a converter failure → the step and its stderr tail;
  - a header check failure (no `stt.variant` or `general.languages`) → refuse to register.

## Files to change
- `healing/healing/export.py` (from `spikes/m0/roundtrip.sh`), `healing/healing/cli.py`
- `healing/tests/test_export.py` (a converter stub for the error paths; the live run uses the real one)
- `healing/vendor/transcribe-cpp.rev`: the pinned converter rev, in one place.

## Decisions
- The converter is fetched into `$HEALING_HOME/tools/transcribe.cpp@<rev>` and built once. It is never vendored into this repo.

## Watch out for
- **Tensor names must equal the base's.** Assert it, as in T0.4.
- **`general.name`** is set to `hex-healing <version>`, so Hex's model list shows which version it is.
- **Disk:** about 3 GB of temp files per export. Clean up on success and failure.

## Acceptance criteria
- `healing export` on the T6.5 smoke delta gives a registered candidate. `hex model import` (isolated) accepts it, and its name shows the version.

## Guardrails and exit criteria

- **X-1:** the converter rejects the merged checkpoint → stop (M0 premise broken).
