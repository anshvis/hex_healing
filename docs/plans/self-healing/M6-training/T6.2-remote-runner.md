# T6.2 - Free cloud fallback (Kaggle) with explicit upload opt-in and cleanup

## Milestone
M6. **Covers:** AC-12, G-3, X-6. **Surface:** backend.

## Branch
`healing/m6-training`.

## Objective
Rounds train on your Mac by default (T6.5, D-34). This task is the optional fallback for when a local round is too slow: Kaggle's free GPUs. Kaggle has no payment method on file, so it can never bill you.

`healing train --remote --allow-upload` does the following:
1. Uploads the prepared bundle as a new **private** Kaggle dataset. The bundle is the WAVs plus the manifest: your voice and words.
2. Pushes a private Kaggle notebook that installs the pinned NeMo, runs T6.5's trainer on the GPU (T4 or P100), and writes the delta and a text-free log.
3. Polls until the notebook finishes, then downloads its output.
4. **Deletes the dataset and the notebook.**

Without `--allow-upload`, it refuses and makes no network call at all.

## Context
- This is the only place personal data leaves the Mac (G-3). It must be explicit, minimal and cleaned up.
- **Kaggle's free tier:**
  - about 30 GPU hours a week;
  - a notebook session is cut off at 12 hours;
  - notebooks need internet on (a phone-verified account) to install NeMo.

  One round, about an hour on a T4, fits easily.
- **Credentials:** Kaggle's own `~/.kaggle/kaggle.json` API token (0600). Never stored in `healing`.

## Domain model
Source: inferred.
- **`$HEALING_HOME/remote/runs.jsonl`:** `{run_id, provider: "kaggle", dataset, kernel, uploaded_bytes, gpu_minutes, started_at_ms, finished_at_ms, deleted_remote: bool, error}`.

## API
- **`healing train --remote [--allow-upload] [--max-minutes 120]`**
- **Errors:**
  - no `--allow-upload` → exit 5, "refusing to upload personal audio without --allow-upload";
  - no Kaggle token → exit 6, naming the token page (kaggle.com › Settings › API › Create New Token) (X-6: park);
  - the weekly GPU quota is used up → exit 7, naming when it resets. The round stays queued for the local trainer or the next week.
  - a remote failure → still deletes the dataset and notebook, then exits non-zero;
  - a failed delete → logs `deleted_remote: false` and prints the exact `kaggle datasets delete` / `kaggle kernels delete` commands.
- **Side effects:** an upload, a GPU run, a download.

## Decisions
- **D-34:** local first; Kaggle is the free fallback. Modal and RunPod are out, because they bill a card once free credit runs out.
- **The bundle is the train split only.** Test sets are never uploaded, since evaluation runs locally in Hex's runtime (T3.3).
- **Everything is private.** The dataset and the notebook are created private, and the test asserts the metadata says so.

## Watch out for
- **Ctrl-C mid-run:** a `finally` deletes the dataset and the notebook.
- **Logs outlive a run.** Kaggle keeps a notebook's output log until the notebook is deleted. Set NeMo's `log_prediction: false` and keep only loss and WER in stdout. Assert in the test that the runner's log filter drops any line containing manifest text.
- **Versions on Kaggle drift.** Pin torch and NeMo in the notebook to T0.4's environment (D-29), and record the versions in the run.

## Acceptance criteria
- Without the flag: exit 5, and no network.
- With the flag and a token:
  - a run completes;
  - `deleted_remote` is true;
  - the delta is downloaded;
  - `kaggle datasets list --mine` shows no healing dataset afterwards.

  **This live check is parked until you add a Kaggle token.**

## Guardrails and exit criteria
- **G-3:** `rg -n 'import (requests|httpx|kaggle)|urllib' healing/healing` → only `remote/` and `sets/`.
- **X-6:** a missing token parks the live check. Local training (T6.5) still works.
