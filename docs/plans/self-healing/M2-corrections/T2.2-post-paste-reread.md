# T2.2 - Watch the retained element for up to 30 s and align the pasted span

## Milestone
M2 - Correction capture. **Covers:** AC-5. **Surface:** backend (a worker in Hex).

## Branch
`healing/m2-corrections`.

## Objective
For up to 30 s after a paste, watch the retained element (D-8). Read its text, bounded, on any of:
- the first tick after the paste (the baseline read);
- an `AXValueChanged` notification, read on the tick that saw it (at most every 40 ms; a field that reports no changes is read every 400 ms);
- focus leaving the element, or the app losing focus;
- Return, only if it emptied or shortened the field (a send; in a notes app it is a newline and the watch goes on);
- +30 s.

Keep the **last read in which the field still contains a match** for the pasted text. A chat app clears the field when it sends, so that read is the edited version just before sending.

From that read, align the inserted text against the field and produce a `CorrectionObservation`.

## Context
- Changed after the challenge (findings 4 and 6). A single +30 s read misses the common case: you fix a word in a chat box and press Return within seconds. An anchor-only locator fails on edits to the first or last word, which is "send it to Kip" → "Kit".
- The bounded AX reads to reuse:
  - `copy_string_capped(el, "AXValue", 4096)` (`src/accessibility.rs:221`; the watcher's own `read_value_bounded` checks `CFStringGetLength` before copying);
  - ranged reads (`:497`);
  - `AXNumberOfCharacters`.
- The secure-field check is at `:158`.
- `CfObject` already wraps CFRetain and CFRelease (`:435`, `:511`).
- `AXObserver` is new to Hex. Run its callbacks on the watcher's own CFRunLoop thread, never on the main thread or the audio thread.

## Domain model
Source: inferred.

### `CorrectionObservation` (stored by T2.3)
- **outcome:** `unchanged`, `edited`, or `lost` with a reason: `element_gone`, `secure`, `too_large`, `span_not_found`, `read_timeout`, `cleared_before_read`.
- **trigger:** `value_changed`, `focus_out`, `return`, or `timeout`.
- **observed_at_ms.**
- **edited_text:** `Option<String>`, only for `edited`. The aligned field span, capped at 2 × the inserted length + 64 characters.

## API
Source: inferred.
- **`correction_watch` worker:** one thread with a CFRunLoop. Each target registers an `AXObserver` for `kAXValueChangedNotification` and `kAXFocusedUIElementChangedNotification` on the app. It unregisters at 30 s, on the first focus-out or app deactivation, or on a Return that cleared or shortened the field. At most 4 targets are watched at once; extra targets wait in the bounded queue from T2.1.
- **`accessibility::read_value_bounded(&RetainedElement, max_chars: 8192) -> Result<String, ReadError>`:** reads the whole `AXValue` when the field has 8,192 characters or fewer. Otherwise it reads a ±4,096 window around the caret.
- **`locate::align(field: &str, inserted: &str) -> Alignment`:** token-level local alignment (Smith-Waterman) of the inserted tokens against the field tokens:
  - match +2, mismatch −1, gap −1;
  - phonetic-insensitive; a plain token match on case- and punctuation-folded tokens.

  Result:
  - **`unchanged`:** an exact substring. The last occurrence nearest the caret wins.
  - **`edited`:** the aligned core alone covers at least 50% of the inserted tokens (or all of them if there are fewer than 3). The span runs from the first to the last aligned field token, extended by at most one field token at each end that has an inserted token left over (so a replaced first or last word stays in), never across sentence punctuation. A lone word replaced by a lone word is the whole field.
  - **`span_not_found`:** anything else.

## Watch out for
- **Edits to the first, last or only word** (the challenge's example). The alignment handles them; test each.
- **A paste sent unedited:** no change is ever reported, so the baseline read is the one kept (`unchanged`, not `cleared_before_read`).
- **The field cleared by send:** keep the last matching read, so the trigger is `value_changed` with the read before the clear. If no read matched, the outcome is `cleared_before_read`.
- **Typing a new message after the edit,** in the same field. The alignment still finds the edited span, because the new text sits outside the local alignment.
- **The same text pasted twice:** the occurrence nearest the caret wins.
- **U+FFFC** (attachments) is stripped.
- **Debounce storms** (every keystroke fires `value_changed`): one read per tick that saw a change, a burst inside a tick is one read, and a cap of 200 reads per target that found the field changed.
- **Quit with watches pending:** unregister and drop inside `process_exit`'s 5 s deadline.
- **Never observe Hex's own pid.** Re-check the lab gate at every read.

## Acceptance criteria
- `locate::align` gives:
  - `edited` with span "send it to Kit" for the inserted "send it to Kip";
  - `edited` for "Kip said hi" → "Kit said hi" (first word);
  - `edited` for the single word "Kip" → "Kit";
  - `unchanged` for the identical text;
  - `span_not_found` for an unrelated field.
- Live, in a chat field: edit and press Return within 5 s, and the result is `edited`.
