# T2.2 - Watch the retained element for up to 30 s and align the pasted span

## Milestone
M2 - Correction capture. **Covers:** AC-5. **Surface:** backend (a worker in Hex).

## Branch
`healing/m2-corrections`.

## Governing invariant
**Fail closed: never store text that is not the user's edit of the paste; any ambiguous read stores nothing.** Where two keystroke histories give the same reads and one of them stores outside text, the answer is lost (real corrections are lost with it, which is accepted: round 9 recall cost in `docs/features/corrections.md`). Hex stores an edit only from a region it is following, and only text inside the paste's own region in the current field (what now occupies the place the pasted text occupied), never text from before or after it. When unsure, return not found or unchanged. Never store an edited span until the paste's landing has been observed; a lost region stays lost. `correction_watch/property_tests.rs` checks it over 30 generated actions across five modes (caret known, a few units off, none, blank lines collapsed, windowed): a 2,382-run default subset and a 208,731-run ignored run, 0 stored outside the region, 0 from a deleted paste, 0 inexact edge spans, 0 known-good edits missed. The previous design under the same default subset: 13, 0, 20 and 29 of 111.

## Objective
For up to 30 s after a paste, watch the retained element (D-8). Read its text, bounded, on any of:
- the first tick after the paste (the baseline read);
- an `AXValueChanged` notification, read on the tick that saw it (at most every 40 ms; a field that reports no changes is read every 400 ms);
- focus leaving the element, or the app losing focus;
- Return, only if it emptied or shortened the field (a send; in a notes app it is a newline and the watch goes on);
- +30 s.

Keep the **last read in which the field still contains a match** for the pasted text. A read that holds other, non-empty text drops it (a later full rewrite is `span_not_found`), except the app clearing the field after a send, which ends the watch with the kept read, but only after a Return (Cmd+Return too): within 1 s of it the field blank, shorter or holding other text (the tap counts Return before the app handles it, so the Return read sees the field still full and the clear arrives a tick later). A field that goes blank with no Return (a send button, or select all and delete) is `cleared_before_read`: a send button without a Return loses the observation. A chat app clears the field when it sends, so that read is the edited version just before sending.

From that read, align the inserted text against the field and produce a `CorrectionObservation`.

## Context
- Changed after the challenge (findings 4 and 6). A single +30 s read misses the common case: you fix a word in a chat box and press Return within seconds. An anchor-only locator fails on edits to the first or last word, which is "send it to Kip" → "Kit".
- The bounded AX reads to reuse:
  - `copy_string_capped(el, "AXValue", 4096)` (`src/accessibility.rs:221`; the watcher's own `read_value_bounded` checks `CFStringGetLength` before copying);
  - ranged reads (`:497`);
  - `AXNumberOfCharacters`.
- The secure-field check is at `:158`.
- `CfObject` already wraps CFRetain and CFRelease (`:435`, `:511`).
- `AXObserver` is new to Hex. Run its callbacks on the watcher's own CFRunLoop thread, never on the main thread or the audio thread.

## Domain model
Source: inferred.

### `CorrectionObservation` (stored by T2.3)
- **outcome:** `unchanged`, `edited`, or `lost` with a reason: `element_gone`, `secure`, `too_large`, `span_not_found`, `read_timeout`, `read_failed` (a failure that is not a timeout, such as a field with no string value: a web view or terminal), `cleared_before_read`.
- **trigger:** `start` (the baseline read), `value_changed`, `focus_out`, `return`, or `timeout`.
- **observed_at_ms.**
- **edited_text:** `Option<String>`, only for `edited`. The aligned field span, capped at 2 × the inserted length + 64 characters.

## API
Source: inferred.
- **`correction_watch` worker:** one thread with a CFRunLoop. Each target registers an `AXObserver` for `kAXValueChangedNotification` and `kAXFocusedUIElementChangedNotification` on the app. It unregisters at 30 s, on the first focus-out or app deactivation, or on a Return that cleared or shortened the field. At most 4 targets are watched at once; extra targets wait in the bounded queue from T2.1.
- **`accessibility::read_value_bounded(&RetainedElement, max_chars: 8192) -> Result<FieldText, ReadError>`:** reads the whole `AXValue` when the field has 8,192 characters or fewer; otherwise a window of that size around the caret. `FieldText` is `{ text, windowed }`. A field with no string value is `ReadError::Failed`, never an empty field. `accessibility::caret` reads the location of `AXSelectedTextRange` before the paste.
- **`locate::Tracker::new(inserted, Option<Anchor>, Option<before text>)` (`None` before text follows nothing) and `Tracker::read(&FieldText) -> Alignment`:** an edit is stored only from a region the tracker is following; `Anchor` is the caret's UTF-16 location alone. With a caret anchor it lands on a read where exactly one copy of the paste's words starts within 8 units of the anchor and that copy was not in the field before the paste (copies from before are tracked through every change since, so one brought near the anchor never lands; two new near copies, or an old one beside the new, lose the tracker). Text typed before the paste arrives moves the anchor first, through the region's own change locator. With no caret, the first read where the paste occurs exactly once, and not in the text read before the paste (`known == Some(0)`), adopts it; a copy held before, twice, or an unread field before makes it lost. The region is followed by diffing each read against the last: typing before moves it, inside stretches it, after leaves it; a change across an edge, or one that could as well sit on either side of one (checked on every path, an open edge included), loses it. Rules (D-8, round 8): **R1** a followed region never holds more words than the paste had, and the words put back at an open edge never exceed the whole words taken away at that edge (a room per edge), so any change that would make it is lost (one word for two, "Kitchen and then" after "Kit chen", "Kit my password is hunter2", words taken at the start and put at the end); **R2** an edge opens when a change takes or replaces its whole edge word, by the characters of the change (backspace, selection, typing over, forward delete; a part of a word edited or deleted opens nothing) and stays open through changes that keep it, keys typed right at it are inside within R1, whitespace typed there closes it and is never part of the region (a space while the paste's words are not all used is lost, never cut short; a line break always closes; so does a replacement that ends in whitespace), keys glued to the last word are that word, an edge beside words typed right outside it never opens; **R3** the ambiguity check runs on every path, and a window that crosses an edge only over whitespace is a reading too (clipped to the region, and one that deletes the whole region, or puts text in its place, disagrees with the rest, so a one-character region deleted with its space is lost); **R4** landing provenance (above), which needs the field read before the paste (without it nothing is followed, caret or not), and an old copy's start moves on when text is inserted at it; **R5** a window, blank included, is checked before a blank read; **R6** a word that overlaps the region and runs out of it (joined to the text beside it) loses the region, never stored whole; **R7** a change that reaches an edge and puts in words beginning with the separator the region keeps (or ending with the one before it) could as well have been typed past it, outside the region, and is lost. Two changes in one read (more than one word-level hunk) lose the region. A blank read retires a followed region (before landing it is only noted), a window retires the tracker, and a lost region stays lost. `judge` reads only the text in the region: unchanged if the paste is a run in it; for one or two words whatever sits there (position is evidence; the budget keeps it from growing); for more, half the words (exact or near) in order, two exact; an empty region or an unrelated one is not found. There is no whole-field edit path.

  Result:
  - **`unchanged`:** the whole words of the pasted text as a run in the field (in the followed region).
  - **`edited`:** the text now in the followed region, trimmed, capped at 2 × the inserted length + 64 characters, for a region that is not the paste intact and that `judge` accepts. Never text outside the region and never from a deleted paste.
  - **`span_not_found`:** anything else. The paste deleted whole is this too.

## Watch out for
- **Edits to the first, last or only word** (the challenge's example). The followed region handles them; test each.
- **A paste sent unedited:** no change is ever reported, so the baseline read is the one kept (`unchanged`, not `cleared_before_read`).
- **Async clear after Return, then the next message typed:** the first read after the Return that shows the field emptied, shorter or different ends the watch with the read kept at the Return.
- **A field with no string value** (web views, terminals) is `read_failed`, never an empty field.
- **Windowed reads** (fields over 8,192 characters) only show the paste whole (`unchanged`) or not at all; a window that cuts the paste is never an edit.
- **Short inserts** match whole words (`Yes` is not in `Yesterday`); a one-word insert is an edit only when the field is that one word.
- **Known gaps:** text without whitespace (CJK) is one token, so effectively unsupported; a send button without a Return loses the observation (a blank field looks like delete-all); a keystroke sharing a tick with the Return is never read (the edit kept is the word as far as it was read); a window over 8,192 characters is never followed; two changes in one read lose the region; an app whose selection offsets are not UTF-16 units gets unchanged or lost only.
- **The field cleared by send:** keep the last matching read, so the trigger is `value_changed` with the read before the clear. If no read matched, the outcome is `cleared_before_read`.
- **Typing a new message after the edit,** in the same field: it is typed after the region, which does not grow to hold it (the region may never hold more words than the paste had).
- **The same text pasted twice, or the paste's text elsewhere in the field:** anchored, only the region at the anchor counts. Strict, an intact copy anywhere is `unchanged`.
- **U+FFFC** (attachments) is stripped.
- **Debounce storms** (every keystroke fires `value_changed`): one read per tick that saw a change, a burst inside a tick is one read, and a cap of 200 reads per target that found the field changed.
- **Quit with watches pending:** unregister and drop inside `process_exit`'s 5 s deadline.
- **Never observe Hex's own pid.** Re-check the lab gate at every read.

## Acceptance criteria
- `locate::align` gives:
  - `edited` with span "send it to Kit" for the inserted "send it to Kip";
  - `edited` for "Kip said hi" → "Kit said hi" (first word);
  - `edited` for the single word "Kip" → "Kit";
  - `unchanged` for the identical text;
  - `span_not_found` for an unrelated field.
- Live, in a chat field: edit and press Return within 5 s, and the result is `edited`.

## Guardrails and exit criteria
- **G-4:** the worker logs `correction observed outcome=<x> trigger=<t> chars=<n> ms=<t>` and nothing more.
- **G-5:** the gate is re-checked at each read.
- **X-3:** measured in T2.4.
