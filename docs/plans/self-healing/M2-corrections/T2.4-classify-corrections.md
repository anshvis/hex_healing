# T2.4 - `healing label corrections`: map to `raw_text`, phonetic check, app-matrix measurement

## Milestone
M2 - Correction capture. **Covers:** AC-6, X-3. **Surface:** backend.

## Branch
`healing/m2-classify`, base `dev` (Python only). It depends on T2.3 being merged, for the live check.

## Objective
For every collected entry whose `correction.outcome == "edited"`:
1. Align `final_text` with `edited_text` and find the word-level edits.
2. Map each edit back onto `raw_text`.
3. Classify each edit as `acoustic` (the new words sound like the old) or `rewrite` (a change of mind).
4. Store the acoustic reference: `raw_text` with only the acoustic edits applied.

Also measure how often observation works per app (X-3).

## Context
- The brief warns that many edits are changes of mind. Compare against `raw_text`, never `final_text`, so the speech model isn't trained to fix the cleanup step's mistakes.
- `final_text` comes from `raw_text` via:
  - replacements;
  - corrections;
  - optional OpenCode rewrite;
  - transforms.

  The pipeline is described in AGENTS.md under `dictation/processor`.
- D-7 (revised): skip entries with `rewritten: true`. That is the History `processing` record, exposed by T1.1.

## Domain model
Source: inferred (adds to the M1 store).

### `clips` (columns this task touches)
- `correction_outcome` TEXT NULL: unchanged, edited or lost.
- `correction_reason` TEXT NULL.
- `edited_text` TEXT NULL.
- `reference_text` TEXT NULL: `raw_text` with only the acoustic edits applied.
- `label`: becomes `strong` when there is at least one acoustic edit.

### `edits` (new)
- **Columns:**
  - `clip_id` FK
  - `idx`
  - `raw_from` TEXT
  - `final_from` TEXT
  - `to_text` TEXT
  - `kind` TEXT: `acoustic`, `rewrite` or `unmapped`
  - `score_metaphone` INTEGER (0/1)
  - `score_char` REAL
  - `score_phone` REAL
- **Invariants:**
  - `kind` is `acoustic` only if `raw_from` is non-empty (it maps to raw);
  - an insertion or deletion with no counterpart is `rewrite`.

**Before → after:**
- raw "send it to kip", final "Send it to Kip.", edited "Send it to Kit."
- → one edit `{raw_from:"kip", to:"Kit", kind:"acoustic"}`, `reference_text:"send it to kit"`, `label:"strong"`.

## API
Source: inferred.

### `healing label corrections [--since] [--recompute]`
- Processes rows that have a correction and no `edits` yet. With `--recompute`, it re-runs all of them after threshold changes.
- Output: counts by kind.

### `phonetic.classify(old: str, new: str) -> (kind, scores)`
- The D-9 rule:
  - Double Metaphone codes match → acoustic;
  - else normalized character edit distance ≤ 0.6 **and** Metaphone-code edit distance ≤ 0.5 → acoustic;
  - else rewrite.
- Multi-word spans are compared as joined strings, so "a pull" vs "apple" counts.

### `healing report observation`
- Per app: pastes, observed (not `lost`), `span_not_found` rate, and edited rate. This is a diagnostic only.

### `healing protocol corrections` (the X-3 measurement)
- A scripted protocol per app in the matrix (TextEdit, Notes, Slack, Chrome textarea, Safari, VS Code). It runs 10 dictations per app through `HEX_AUDIO_FIXTURE` and `hex dictation start/stop`.
- Half get a **seeded edit**: one word replaced, half of them followed by Return or send within 5 s. The edit is typed with System Events keystrokes, so Hex sees an ordinary edit.
- It reports **edit recall**: seeded edits captured as `edited` with the right span, divided by seeded edits. It also reports the false-edit rate on the unedited half.

## Decisions
- D-7: skip entries with `rewritten: true` (T1.1).
- D-9 thresholds are set by the fixture. The bar is precision of `acoustic` ≥ 0.9 at recall ≥ 0.7, because false acoustic labels poison training more than missed ones.

## Watch out for
- **Casing and punctuation-only edits** ("kit" → "Kit.") are neither kind. Drop them; they're formatting.
- **An edit inside text that a replacement produced** (final has "OpenCode" where raw has "open code"). Map through the alignment; if the final-side span maps to a different raw span, the kind is `unmapped`.
- **Numbers and formatting** ("five" ↔ "5"): normalize numbers before comparing.
- **Homophones** (there/their) are acoustic but carry no speech signal. Keep them; the model learns from context.
- **A strong label with no audio** (evicted, or recordings off): still useful for Tier 1. Mark it `strong_without_audio`.

## Acceptance criteria
- **AC-6:**
  - On the fixture, `acoustic` precision is ≥ 0.9 and recall ≥ 0.7.
  - "Kip→Kit" gives one acoustic edit and `reference_text` "send it to kit".
  - "tomorrow→Friday" is `rewrite` and changes no reference.
  - A rewrite-mode entry is skipped.
- **X-3:** `healing protocol corrections` shows edit recall ≥ 0.5 across the matrix, and a false-edit rate ≤ 0.05. Otherwise trigger X-3 (challenge finding 6: observing a paste isn't the same as capturing its edit).

## Guardrails and exit criteria

- **X-3:** a measured observation rate below 0.5 → NEEDS_REPLAN with the per-app table.
