# T2.3 - Store `correction` on the History entry and expose it in `hex history --json --raw`

## Milestone
M2 - Correction capture. **Covers:** AC-5. **Surface:** backend.

## Branch
`healing/m2-corrections`.

## Objective
Write each `CorrectionObservation` onto its History entry, so it is subject to the same retention, caps, Delete and Clear all. `hex history --json --raw` prints it.

## Context
- History is the only place Hex keeps text (AGENTS.md). T2.5 amends the History invariant in the same PR, so this field is allowed by the rules it lands under.
- `HistoryEntry` is at `src/history.rs:114-148`. Its persistence is a temp → fsync → rename with owner-only modes (`:671-682`).
- Older builds must still read the file. An unknown optional field is ignored (`#[serde(default)]` and no `deny_unknown_fields`); confirm this in `src/history.rs`.
- `--raw` gates `raw_text` in the CLI. Corrections are text too, so they sit behind the same flag.

## Domain model
Source: inferred (edited: a History entry field).

### `history.json` entry
- **Columns touched:** `correction` object, optional:
  - `outcome` string
  - `reason` string, optional
  - `observed_at_ms` u64
  - `edited_text` string, optional, ≤ 16 KiB (the per-text cap)
- **Invariants:**
  - at most one `correction` per entry, and the first observation wins;
  - `edited_text` counts toward `MAX_TOTAL_TEXT_BYTES` (16 MiB);
  - the field is absent for entries with no observation.
- **Before → after:**
  - before: `{id:42, raw_text:"send it to kip", final_text:"Send it to Kip.", …}`
  - after: `{…, correction:{outcome:"edited", observed_at_ms:…, edited_text:"Send it to Kit."}}`

## API
Source: inferred.
- **`History::observe_correction(id: u64, obs: CorrectionObservation) -> io::Result<bool>`**
  - Returns false when the entry is gone or already has a correction. That's idempotent.
  - Persists through the existing path.
  - Callers: the `correction_watch` worker.
- **`hex history --json --raw`:** rows gain `correction` (with `--raw` only).
- **`docs/transcript-cli.md`:** documented, with `version` still 1 (additive).

## Files to change
- `src/history.rs`: the field, `observe_correction`, text-byte accounting, tests.
- `src/history/versions.rs`: none. Corrections belong to the entry, not to a version. A Replace keeps the correction, because it was observed against the pasted text.
- `src/control/transcript_cli.rs`: the projection behind `--raw`, and tests.
- `docs/transcript-cli.md`, `docs/features/corrections.md`.

## Gold-star references
- `src/history.rs:398` (`record`) and the caps accounting near `:304`: the same lock, persist and eviction path.

## Decisions
- Should text be stored only behind `--raw`? Yes. It matches `raw_text`: an agent asking for the plain history gets final text only.

## Watch out for
- **The entry was evicted between the paste and the observation** (caps, Clear all) → false, and nothing is written.
- **Replace (Transcribe again)** rewrites `raw_text` but keeps `correction`, which was observed against the pasted text. `healing` re-derives labels when `raw_text` changes (T1.2 upsert).
- **History retention is Off:** no entry was recorded (`record` returned None), so no target was ever submitted (T2.1). Assert this.
- **An older build loads and saves the file.** It drops `correction`. That's acceptable; document it.
- **Concurrency:** `observe_correction` takes the same mutex as `record`.

## Acceptance criteria
- After `observe_correction(42, edited "Kit")`, `hex history --json --raw` row 42 has `correction.edited_text == "Kit"`. Without `--raw`, the row has no `correction`.
- Clear all removes it.

## Guardrails and exit criteria
- **G-4:** the text lives only in `history.json`. The test greps `live.ndjson` and `process.log` for the edited text → absent.
- **X-4:** if older-build compatibility fails (the file is rejected by `deny_unknown_fields`), stop and replan.
