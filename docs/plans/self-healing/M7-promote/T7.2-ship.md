## Milestone

## Branch
`healing/m7-promote`.

## Objective
`healing promote <v>` (which requires a passing gate record) does the following:
1. Runs `hex model import <gguf> --name "Hex healing v<n>"`.
2. Runs `hex model use custom-<16hex>`.
3. Confirms with `hex status --json` that the selected model is that id.
4. Appends `promoted` and sets it as current.

`healing rollback [--to <v>]` does the reverse: `hex model use` the previous version, re-importing from the registry if Hex no longer has it, then appends `rolled_back(reason)`.

## Context
- `hex model import` copies the file to `models/custom/<16hex>.gguf` with a receipt (`src/transcription/custom_models.rs:303-307`).
- `hex model use` goes through the running Hex, never downloads, and answers `model-unavailable` if the model is missing (`docs/cli.md:224`).
- Model switches activate only after a verified load and prewarm. A failed switch keeps the old model (AGENTS.md invariants).

## API
- **`healing promote <v>`**
  - Errors:
    - no passing gate → exit 8;
    - Hex not running → exit 2, and nothing changes;
    - `hex status` shows a different model after `use` → append `promote_failed` and exit 9.
- **`healing rollback [--to <v>] [--reason <text>]`**

- **The language hint:** Parakeet customs take none (`custom_models.rs:49-52`). Don't pass `--language`.

- **Your own vocabulary and settings are untouched.**
- **Imports pile up**, about 700 MB each. After a successful promote, `hex model remove` every healing import except current, the previous 2 and v0, matched by the registry's sha. Never remove an import healing didn't create.
- **A Unified-based candidate with Labs › Stream imported models off:** refuse, with exit 10 and "turn on Labs › Stream imported models". The gate's `streaming` check would already have failed.
