# T8.4 - Apply accepted edits through Accessibility

## Milestone
M8. **Covers:** AC-17. **Surface:** backend (macOS Accessibility).

## Branch
`healing/m8-tidy`.

## Objective
Apply the accepted suggestions to the text Hex pasted, in the field Hex pasted it into, as **one undoable edit**, and never touch anything else.

## Context
- M2 keeps the focused AX element Hex pasted into and the exact inserted text (`Learn from corrections`).
- Tidy needs the same handle even when Learn from corrections is off. So the handle-keeping moves into a shared piece both labs use, kept only while either lab is on.

## Domain model
Source: inferred.
- **`PasteAnchor`:**
  - the AX element reference;
  - the inserted text's SHA-256 and length;
  - the expected range (UTF-16) right after the paste;
  - the app's pid;
  - `pasted_at`.

  It is held in memory only, never written, and dropped at the next paste or after 10 minutes.

## API
- **`tidy::apply(anchor, edits) -> Applied | Moved | Unsupported`:**
  1. Read the element's `AXValue`. Find the inserted text: at the expected range first, else by a unique exact search.
  2. **Not found, or found twice:** return `Moved`. The capsule says "The text changed since it was pasted", offers Copy tidied text, and changes nothing.
  3. **Found:** build the tidied replacement for that range.
     - Prefer `AXSelectedTextRange` set to the range, then `AXSelectedText` set to the replacement: one undoable edit in most native fields.
     - If the attribute isn't settable (some web views and Electron apps), select the range and paste the replacement with Hex's paste path. That's still one undo step.
  4. **Verify:** re-read the value. The range now holds the replacement and everything outside it is byte-identical; otherwise report the failure.

## Files to change
- `src/accessibility.rs` (anchor capture and range edits), `src/dictation/tidy/apply.rs`, `src/paste.rs` (record the anchor when either lab is on).
- M2's correction-watch code moves to the shared anchor; its behaviour is unchanged.

## Gold-star references
- `src/accessibility.rs`: bounded focused-element reads without the clipboard.
- `src/paste.rs`: generation-safe clipboard restore, for the paste fallback.

## Watch out for
- **Secure text fields** are never read or edited.
- **The user typed after the paste:** the exact-search rule handles text before or after. An edit inside the pasted text means `Moved`.
- **Rich text:** setting `AXSelectedText` may drop styling in the range. Accept that, because the range is Hex's own plain paste.
- **Focus:** the capsule returns focus before applying. Verify that the frontmost pid matches the anchor's, or refuse.

## Acceptance criteria
- **AC-17 (apply):**
  - In TextEdit, Notes, Slack and a Chrome textarea, accepted edits change only the pasted range, and one ⌘Z restores it.
  - Text typed before or after the paste is untouched.
  - An edit inside the pasted text gives `Moved` and no change.

## Guardrails and exit criteria
- **G-4:** the anchor holds a hash and a length, never the text, beyond the in-memory session.
- Never edits a secure field (asserted in code: the role check comes first).
