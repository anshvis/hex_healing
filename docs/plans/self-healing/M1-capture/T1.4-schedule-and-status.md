# T1.4 - launchd schedule and `healing status`

## Milestone
M1 - Long-term capture. **Covers:** AC-3 (no gaps), AC-4 (visibility). **Surface:** backend.

## Branch
`healing/m1-schedule`, base `healing/m1-collector`.

## Objective
- Collection runs every 6 h without you thinking about it.
- `healing status` warns before data is lost: Keep recordings off, a collection gap longer than History's retention, budget pressure, `strong_without_audio`.

## Context
- History keeps 7 days by default, or 1 day when retention is set to Day (`src/history.rs:43-57`).
- `hex settings get labs.keep_recordings` and `hex settings get history.retention` read the live values. Check the exact keys with `hex settings list`.
- With Keep recordings off, `recording` is absent and audio is lost for good.

## Domain model
Source: inferred. It reads T1.2's `runs` and T1.3's `clusters` and `audio`. No new tables.
- **`~/Library/LaunchAgents/com.hex-healing.collect.plist`.** Role: the user launchd job. It runs `healing collect` (which prunes) every 21,600 s and at load. Logs go to `$HEALING_HOME/logs/collect.log` (0600). The log holds counts only, never text (G-4 spirit).

## API
Source: inferred.

### `healing schedule install|remove|show`
- `install` writes the plist with the absolute `healing` and `hex` paths, then runs `launchctl bootstrap gui/$UID`.
- `remove` runs bootout and deletes the plist.
- Both are idempotent.

### `healing status [--json] [--list]`
- **Fields:**
  - `clips`, `with_audio`, `audio_bytes` / `budget`;
  - `labels` by kind;
  - `clusters`;
  - `last_run` (time, new, error);
  - `oldest_uncollected_risk`;
  - `warnings[]`.
- **Warnings:**
  - `keep_recordings_off`;
  - `gap_exceeds_retention`: the last successful run is older than retention minus 1 day;
  - `budget_over_90pct`;
  - `strong_without_audio > 0`;
    - `history_retention_day`;
    - `recordings_hidden`: Keep recordings is off now but WAVs from earlier still exist. `hex history` hides `recording` whenever the lab is off (`src/control/transcript_cli.rs:419`), so turning it off stops collection of audio that's still on disk.
- **Exit codes:** 0, or 1 when any warning is present (so you can script it).

## Decisions
- 6 h interval: four chances a day against a 1-day minimum retention.
- The log keeps counts only.

## Watch out for
- **The Mac is asleep at the interval.** launchd runs the job on wake.
- **`hex` isn't on launchd's PATH.** Store absolute paths at install.
- **Two runs overlap** (a manual run during the scheduled one). The process lock from T1.3 serializes them.

## Acceptance criteria
- `healing schedule install` creates a loaded job (`launchctl print gui/$UID/com.hex-healing.collect` shows it).
- `healing status` warns `keep_recordings_off` when the lab is off, and `gap_exceeds_retention` when the fixture's last run is 7 days old.

## Guardrails and exit criteria
- **G-6:** status reads Hex only through `hex settings get` and `hex history`.
- **G-4:** `collect.log` contains no `raw_text` or `final_text`. A test greps it.
