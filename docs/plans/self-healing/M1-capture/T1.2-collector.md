# T1.2 - `healing collect`: idempotent copy into the dataset

## Milestone
M1 - Long-term capture. **Covers:** AC-3. **Surface:** backend.

## Branch
`healing/m1-collector`, base `healing/m1-history-fields` (stacked) or `dev` once T1.1 merges.

## Objective
`healing collect` copies every History entry into a dataset Hex can't expire:
- `raw_text`, `final_text`, `application`, `mode`, `kind`;
- `model_id`, `timestamp_ms` (no language: decisions.md row 2);
- the audio, as FLAC.

Running it again adds nothing new.

## Context
`hex history --json --raw --since <t> --limit 10000 --oldest-first` is read-only and safe to poll (`src/control/transcript_cli.rs:20-45,416`). `recording` is the absolute WAV path. It is present only while Keep recordings is on and the file exists (`:251-253`).

Entry ids are per-store, monotonic and never reused while the file exists (`src/history.rs` `next_id`). Clearing History doesn't reset `next_id`, but deleting `history.json` does. So the dataset key is `(hex_store_epoch, id)`. The epoch is the timestamp of the lowest id seen, which survives a store reset.

## Domain model
Source: inferred (a new store).

### `dataset.sqlite` table `clips`
- **Role:** one dictation Hex made, as collected.
- **Columns:**
  - `clip_id` TEXT PK: `sha256(epoch:id)[:16]`
  - `hex_id` INTEGER NOT NULL
  - `hex_epoch_ms` INTEGER NOT NULL
  - `timestamp_ms` INTEGER NOT NULL: UTC ms from Hex
  - `application` TEXT NULL
  - `mode` TEXT NULL
  - `kind` TEXT NOT NULL: dictation, send, voice_action, printed or raw
  - `model_id` TEXT NULL: the stable id from T1.1
  - `model_name` TEXT NULL: the display name
  - `rewritten` INTEGER NOT NULL DEFAULT 0
  - `audio_ms` INTEGER NULL
  - `raw_text` TEXT NOT NULL
  - `final_text` TEXT NOT NULL
  - `audio_sha256` TEXT NULL: FK → `audio.sha256`
  - `cluster_id` TEXT NULL: T1.3
  - `label` TEXT NOT NULL DEFAULT `'unlabelled'`: values `unlabelled`, `weak`, `strong` and `verified` (M3)
  - `golden` INTEGER NOT NULL DEFAULT 0
  - `collected_at_ms` INTEGER NOT NULL
- **Keys and invariants:**
  - UNIQUE(`hex_epoch_ms`, `hex_id`);
  - `audio_sha256` NULL means there is no audio, either because the lab was off or the file was gone at collection;
  - Hex mutates entries after creation: a `correction` lands about 30 s later (M2), and Transcribe again → Replace rewrites `raw_text`, `final_text` and `model_id`. Those fields are **upserted** by (`hex_epoch_ms`, `hex_id`). When `raw_text` changes, the row's labels are recomputed (M3). Otherwise only `cluster_id`, `label`, `golden` and audio eviction change.

### `dataset.sqlite` table `audio`
- **Role:** one stored audio blob.
- **Columns:**
  - `sha256` TEXT PK, of the decoded PCM
  - `path` TEXT NOT NULL: `audio/<aa>/<sha256>.flac`
  - `bytes` INTEGER NOT NULL
  - `samples` INTEGER NOT NULL
  - `evicted_at_ms` INTEGER NULL
- **Invariants:**
  - the file exists if and only if `evicted_at_ms IS NULL`;
  - the sample rate is 16000, the format mono s16;
  - the same PCM collected twice is one row.

### `dataset.sqlite` table `runs`
- **Role:** one collector run.
- **Columns:** `run_id`, `started_at_ms`, `since_ms`, `seen`, `new`, `audio_new`, `missing_audio`, `error`.

**Before → after:**
- History has id 42 with a WAV, and the dataset has nothing.
- After `collect`: `clips` gains a row with `audio_sha256=ab12…`, and `audio/ab/ab12….flac` exists.
- Hex later expires 42. The row and the file remain.

## API
Source: inferred.

### `healing collect [--since <dur|date>] [--hex <path-to-hex>]`
- **Signature:** reads `hex history --json --raw --oldest-first --limit 10000 --since <min(last run's newest timestamp − 2 days, …)>`. The 2-day trailing re-scan picks up corrections and Replace edits on entries already collected. `--since` accepts `3d`, a date or RFC 3339, not epoch ms.
- **Output:** a summary `seen N, new M, audio K, missing_audio J`.
- **Errors:**
  - `hex` not found → exit 2;
  - the history JSON `version` isn't 1 → exit 3, refusing;
  - a WAV path that can't be read → the row is stored without audio, counted as `missing_audio`, and the run continues.
- **Side effects:** inserts rows, writes FLAC files (temp, fsync, rename, 0600), and appends to `runs`. Never writes outside `$HEALING_HOME` (G-6).
- **Idempotency:** UNIQUE(`hex_epoch_ms`, `hex_id`) with `INSERT … ON CONFLICT DO UPDATE` of the mutable fields only, and only when they differ. Audio is keyed by PCM hash. A crash mid-run leaves no partial FLAC (temp files are swept at start).
- **Callers:** you, and the launchd job (T1.4).

## Decisions
- Parse JSON, or read `history.json` directly? Parse `hex history --json`. It is the documented, versioned contract, and it applies retention at query time.
- Which version of Replace? `hex history` shows the current `raw_text`/`final_text`. When `model` differs from the model that heard the audio, store the row anyway. T3.1 decides usability by `model`.
- Text-only entries (no audio)? Store them. Tier 1 vocabulary mining uses them.

## Watch out for
- **`--limit 10000` is the maximum.** Page by advancing `--since` to the last `timestamp_ms` seen, deduplicating by id. Equal timestamps at the boundary must not drop rows.
- **A Hex store reset** (history.json deleted) restarts ids at 1. The epoch key prevents collisions. Detect it: the lowest id seen is lower than the stored max for the epoch, and timestamps are newer.
- **Empty History, retention Off,** or `hex` not running. `hex history` reads the file directly, so collection still works without Hex running.
- **The WAV disappears between the JSON read and the copy** (Hex sweep race). Count it as `missing_audio`; don't fail.
- **Large backlog:** 10,000 rows × 10 s. Stream them and commit in batches of 500.
- **Text with secrets.** The dataset is owner-only (0700 dir, 0600 files), the same bar as Hex's History.

## Acceptance criteria
- **AC-3** Against a fixture history with 3 entries (2 with audio), the first `collect` stores 3 rows and 2 FLACs. The second stores 0. After an entry is removed from the fixture, a third run leaves all 3 rows and 2 FLACs intact. The FLAC decodes to the WAV's PCM exactly.
