# T1.1 - History records a stable `model_id`, and `hex history --json` exposes it with `audio_ms` and `rewritten`

## Milestone
M1 - Long-term capture. **Covers:** AC-3 (provenance fields). **Surface:** backend (History store field and CLI JSON).

## Branch
`healing/m1-history-fields`, base `dev`. A small Rust PR of its own, so the Python work never waits on Rust review.

## Objective
- Every new History entry records the **stable id** of the model that actually transcribed it, taken from the job's own selection:
  - the catalog id, or `custom-<16hex>` for an import.
- `hex history --json` rows carry `model_id`, `audio_ms`, and `rewritten`. `rewritten` is true when an OpenCode rewrite produced `final_text`.

## Context
Changed after the plan challenge (finding 2):
- History's `model` is a **display name** from `dictation_model()` (`src/history.rs:221-230`), read when the entry is recorded, after inference. It is wrong in two ways:
  - imports can be renamed (`hex model rename`);
  - a model switch between inference and recording mislabels the entry.
- `language` is always `None` for dictations (`src/history.rs:431`), so it isn't exposed.
- `HistoryDraft` is built in `src/dictation/modes.rs:131-150` (`model: crate::history::dictation_model()`) and in `src/parakeet.rs` `record_history` (`:1208-1235`).
- `HistoryProcessing { profile, latency_ms, fallback }` (`src/dictation/modes.rs:138-142`) exists only when mode processing ran. `fallback` is set when the rewrite failed and the corrected transcript was used. So `rewritten = processing.is_some() && fallback.is_none()`. Confirm this against `dictation/processor` before relying on it (X-4 if it doesn't hold).

## Domain model
Source: inferred (edited: a History entry field).

### `history.json` entry
- **Columns touched:** `model_id` string, optional. The stable selection id of the model that ran the job.
- **Invariants:**
  - set from the job's selection at submission, never from global state at record time;
  - absent on entries written before this change;
  - older builds ignore the unknown field (confirm there is no `deny_unknown_fields`).
- **Before → after:**
  - before: `{…, model:"Parakeet Unified English"}`
  - after: `{…, model:"Parakeet Unified English", model_id:"parakeet-unified-en"}`

### `hex history --json` row
- **Columns touched:**
  - `model_id` (optional);
  - `audio_ms` (optional, omitted when 0);
  - `rewritten` (bool, omitted when false).
- **Invariant:** `version` stays 1, because the fields are additive.

## API
Source: inferred.

- **`hex history --json [--raw]`:** rows gain the three fields. Callers: `docs/transcript-cli.md` consumers and the TypeScript SDK (`rg -n history sdk/typescript/src`). MCP doesn't use this row.

## Decisions
- Keep `model` (the display name) for the UI; add `model_id` beside it. Renaming the old field would break History's display and older readers.
- `language` is dropped from scope: it is always None today.

## Watch out for
- **A model switch while a job is in flight.** The id comes from the job, not `TranscriptionEngine::shared().held_selection()` at record time. Test it: switch the model between submit and record.
- **Apple Speech:** the engine never holds it. Use its selection id the same way.
- **Older entries** have no `model_id`; omit it, never `"unknown"`.
- **`audio_ms == 0`** on Printed or Raw kinds; omit it.

## Acceptance criteria
- A dictation recorded after this change has `model_id` equal to the selection its job ran, even if the model was switched before the History write.
- `hex history --json` shows `model_id`, `audio_ms` and `rewritten` (when true). Old entries omit them.

## Guardrails and exit criteria
- **G-4:** metadata only, no new text.
- **X-4:** if `rewritten` can't be derived from `HistoryProcessing`, stop and replan. The fallback is D-7's skip rule with a different signal.
