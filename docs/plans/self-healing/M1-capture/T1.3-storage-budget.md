# T1.3 - Near-duplicate clusters, k audio per cluster, byte budget

## Milestone
M1 - Long-term capture. **Covers:** AC-4. **Surface:** backend.

## Branch
`healing/m1-storage-budget`, base `healing/m1-collector`.

## Objective
Storage stays bounded however long Hex runs, while new and unusual speech keeps being admitted:
- near-duplicate dictations share a cluster;
- each cluster keeps audio for at most k clips, chosen for acoustic spread;
- a byte budget evicts the most redundant, oldest weak audio first.

## Context
At 10 s per dictation, a FLAC is about 170 KB. 100 dictations a day is about 6 GB a year without pruning.

You repeat phrases. Copies of the same words teach the model little, and they leak across test sets (M3 splits by cluster).

Strong labels are the scarce, valuable data, and so are verified and golden clips. Keep all of them (AC-4). At about 200 a week, that is under 2 GB a year, so it scales.

## Domain model
Source: inferred (adds to T1.2's store).

### `clips` (columns this task touches)
- `cluster_id` TEXT NULL: the representative clip's id.
- `redundancy` REAL NOT NULL DEFAULT 0, in [0, 1]: how similar the clip is to its cluster's kept audio.

### `clusters` (new)
- **Columns:**
  - `cluster_id` TEXT PK
  - `norm_text` TEXT: the normalized representative `raw_text`
  - `size` INTEGER
  - `audio_kept` INTEGER
  - `last_seen_ms` INTEGER
- **Invariants:**
  - `audio_kept ≤ k` (default 3), except that protected clips (strong, verified or golden) always keep audio and don't count toward k;
  - every clip with a non-null `raw_text` has a cluster.

### `audio.evicted_at_ms`
Set when the file is removed. The clip row and its text stay.

**Before → after:** cluster "send it to kit" has 7 weak clips with audio, and k=3. After `prune`, it has 3 kept (the most acoustically spread, newest among ties) and 4 with `evicted_at_ms` set, their rows intact.

## API
Source: inferred.

### `healing prune [--budget 5GiB] [--k 3] [--dry-run]`
- **Order:**
  1. Cluster new clips.
  2. Enforce k per cluster.
  3. If the total audio still exceeds the budget, evict by descending `evict_score = redundancy × age_decay(t)`, where the half-life is 90 days.
- **Output:** the list of evictions in dry-run, or the summary `evicted N (B bytes), total T / budget`.
- **Errors:**
  - the protected audio alone exceeds the budget → exit 4, naming the overage;
  - nothing is evicted and nothing is lost.
- **Side effects:** deletes FLAC files and sets `evicted_at_ms`. Never deletes rows.
- **Idempotency:** clustering is deterministic given the clip order (`timestamp_ms`, then `clip_id`). A re-run without new clips evicts nothing more.
- **Callers:** `healing collect` runs `prune` after each run (T1.4), and you.

### `dedupe.cluster(clips) -> assignments`
- **Text similarity:**
  - normalize (lowercase, strip punctuation, collapse whitespace);
  - token 3-gram MinHash (128 perms) with LSH;
  - Jaccard ≥ 0.8 and duration ratio within ±30% → same cluster (D-6).
- **Acoustic spread:** per-clip MFCC (13 coefficients) mean and variance vector. Kept clips are chosen by greedy max-min distance.

## Decisions
- These clusters are for **storage** (redundancy). Test-set splitting uses a different, stricter grouping: connected components on `reference_text` with no duration condition (T3.2, challenge finding 10).
- D-6 thresholds (0.8 Jaccard, ±30% duration, k=3) and a 5 GiB budget. These are defaults; `--k` and `--budget` override them.
- Short texts (fewer than 3 tokens) use whole-text equality, because 3-grams don't exist.
- Does clustering use `raw_text` or `final_text`? `raw_text`, which is what was heard.

## Watch out for
- **Protected clips:**
  - never evicted, whatever the budget;
  - never counted toward k;
  - "protected" is re-evaluated each run, because a clip can become strong later (M2).
- **An evicted clip later becomes strong.** Its audio is gone, so it can't be restored. Count it as `strong_without_audio` in `healing status`. This is why the budget should be generous and correction capture runs before eviction. Prune skips clips younger than 7 days.
- **Empty `raw_text`:** no cluster, no eviction preference.
- **A cluster's representative is evicted.** The cluster id stays; it's only a key.
- **Concurrency:** `collect` and `prune` share one process lock (`$HEALING_HOME/.lock`).
- **Budget smaller than one file** → exit 4.

## Acceptance criteria
- **AC-4** With a fixture of 50 clips (one phrase said 20 times, 30 unique, 2 of the repeats strong):
  - `prune --k 3` keeps 3 + 2 audio files in the repeated cluster and all 30 unique;
  - with `--budget` set to 25 files' worth, it evicts only weak redundant audio, and the total ends at or under budget;
  - adding 10 new unique clips and running again admits all 10.

## Guardrails and exit criteria
- **G-6:** touches only `$HEALING_HOME`.
- **X-2-like:** the protected set exceeds the budget on your real data → report it. Don't evict protected clips.
